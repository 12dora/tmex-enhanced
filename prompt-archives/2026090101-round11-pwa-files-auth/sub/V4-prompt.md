A re-review found two remaining defects:

1. **Major — sized cold select lost its ordering guarantee.** `applyTmuxSelection` (`tmux-command-handlers.ts` ~139) now issues an **unsized** `selectPane` and fires the resize separately through `applyViewportPolicy`. `SessionCommands.fire()` does not serialise operations (`apps/gateway/src/tmux-client/external/session-commands.ts` ~698), so history capture (~620) can run before the resize completes; previously `selectPaneWithSize` resized (612–614) *before* capturing history, and the client relies on history being captured at the requested geometry (see `writeRestoredHistory` semantics). Also, when the cached snapshot already equals the requested geometry the resize is skipped entirely even if tmux drifted. Fix: **resolve ownership first** (record the claim, compute the winner for the pane's window), then dispatch: owner → the existing ordered `selectPaneWithSize` path exactly as before (resize then capture); follower → unsized `selectPane` (and, if the window's live geometry differs from the winner's, re-apply the winner geometry before the select so history is captured at the authoritative size). Single-client behaviour must be byte-identical to pre-round-11 (`selectPaneWithSize` used for every sized select). Tests: runtime-level test proving the resize completes before history capture for an owning sized cold select (`wantHistory: true`), including the "cached geometry equal but tmux drifted" case and the reconnect case; follower sized select → no resize to follower size, history captured at owner size.

2. **Major — claim reconciliation only runs for the key passed to `applyViewportPolicy`; snapshot installs never reconcile.** Snapshot delivery just replaces `entry.lastSnapshot` and broadcasts (`legacy-feed-broadcaster.ts` ~186). After a pane moves window (break/join) or a window closes, stale claims stay under the old key (and the frontend claim effect has no window-id dependency, so no new claim arrives). Fix: when a new snapshot is installed for a device entry, reconcile **all** claims of all sessions on that entry against it — drop claims for missing panes/windows, re-key claims whose pane moved, prune `lastAppliedViewport`/`lastViewportWinnerId` for gone windows — and recompute/apply/notify for every affected window (source and destination). Keep it off the per-output-frame path (snapshot installs only). Replace the current test that manually calls `applyViewportPolicy` for the old key with one that delivers the moved/closed-window snapshot through the real snapshot install path and asserts the re-keying, the cleanup, and that the destination window is arbitrated.
