# RV3 — Multi-client terminal viewport policy (largest visible client owns the tmux window size; followers pan locally)

Contract: `prompt-archives/2026090101-round11-pwa-files-auth/sub/T-contract.md` (read it). Design doc: `docs/terminal/2026090101-viewport-policy.md`. Decisions already made: one shared PTY per pane; C2S `TERM_VIEWPORT {deviceId,paneId,cols,rows,visible}`; S2C `TERM_VIEWPORT_POLICY {deviceId,windowId,paneId,owner,cols,rows}`; `terminal-resize`/`terminal-sync-size` count as visible claims; winner = max cols*rows, cols, rows, lowest session id; tmux resized only when winner geometry changes; followers use `sizingMode='follow'` + `viewportPan` (content surface at PTY geometry inside a two-axis scrollable viewport; touch nested-scroll: pan first, then scrollback).

Review for: (1) **single-client regression** — with exactly one browser, is every resize applied exactly as before (including the first resize after connect, split windows via `resizeWindow`, `terminal-sync-size` after selection, reconnect)? Trace `handleTermResize` before/after; (2) claim lifecycle leaks/stale winners: session close, device detach, reconnect-failure cleanup ("drops without recompute" — can a dead session keep owning the size until someone else resizes?), pane→window remap when panes move between windows, unknown pane; (3) policy flapping: two clients with equal geometry; owner hides/unhides rapidly; follower→owner forced report timing (`scheduleResize('sync', {immediate, force})`) — could the follower's stale container size be reported before its ResizeObserver measured?; (4) `use-viewport-claims.ts`: `visibilitychange` on iOS PWA (page hidden → claims withdrawn → desktop becomes owner → phone returns and re-claims — does it re-assert with the right geometry? dedup logic: could a needed claim be suppressed after reconnect?); (5) `use-pane-size-sync.ts` now resizes via `TerminalRef.resize()` — history rebuild correctness for followers and for hidden keep-alive instances; (6) ghostty pan viewport: hit-testing when panned (selection, mouse reporting, links, IME/textarea placement), `touch-action:none` side effects on the non-pan case, scroll offset reset when `viewportPan` toggles off, memory/DOM identical when off; (7) gesture machine: axis lock rules, reporting-mode wheel untouched, `scroll-bypass` fallback; (8) protocol: kind numbers don't collide, decoder tolerant of unknown kinds for older gateways/clients (new client vs 1.1.6 gateway and vice versa during a rolling upgrade — what happens?).
