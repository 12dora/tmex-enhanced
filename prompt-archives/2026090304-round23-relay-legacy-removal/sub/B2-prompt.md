## Implementation notes
- Reuse: link mux / WebSocketLink from @tmex/shared/link (see how apps/gateway/src/hub/uplink-server.ts accepts uplinks: challenge nonce, sig = Ed25519(nonce ‖ host), stream pump for relay streams ~1725-1783, rate limiter apps/gateway/src/hub/uplink-rate-limit.ts, heartbeat) — copy patterns, do not import hub internals that drag in user-store assumptions. Argon2id for the relay password: use the same hash-wasm argon2id already used for root keys (packages/shared/src/auth) with a random 16-byte salt; store `$argon2id$...` style string or JSON {salt, hash, params}.
- Tenant token: 32 random bytes b64url; store sha256; `token_epoch = password_epoch` at issue; valid iff `token_epoch >= min_token_epoch` and tenant not kicked.
- `POST /api/relay/enroll`: verify `proof` via shared `verifyRelayEnrollProof` (ts skew ≤ RELAY_ENROLL_PROOF_MAX_SKEW_MS), password check (constant-time; if `password_hash` is null skip), per-IP limiter (5 failures / 15 min). Re-enroll with the same root_public_key → same tenant_id, new token, clears kicked flag.
- `relay.auth`: per plan 1.8. Member proof: admit-node record bytes+sig; use the shared key-log verification primitives to validate a root-signed record against the tenant's root_public_key/root_epoch (the record's own signer field says root vs passkey); extract node_id / ed_pk / x25519_pk from the certificate inside. `revoke` in `relay.keylog.append.member`: root-signed only.
- Registry in memory (tenant → nodes → live link, latest status blob), persisted rows for offline knowledge. `relay.list` broadcast to the tenant's online nodes on: auth ok, status update, membership change, disconnect (debounce 100 ms).
- Quotas: effective = tenant.quota ?? config.default_quota; maxNodes enforced at redeem (pending+admitted count); maxStreams enforced at OPEN (RST with a reason frame if the link supports it, else RST); bandwidth: token bucket per tenant applied to relay stream DATA pumping (delay, never drop). Metering: bytes in/out per tenant in memory, flushed to relay_tenants every 30 s and on shutdown; `GET /api/relay/status` merges live + persisted.
- Admin auth middleware: bearer `TMEX_RELAY_ADMIN_TOKEN` (constant-time compare) OR a hook `isLocalUserAuthenticated(req)` injected by assemble when node role is present (mesh withAuth) — accept an injected async predicate so you do not import mesh code.
- Key log storage: `relay_key_log` blobs; `seq` must equal head+1 per tenant; page `relay.keylog.req` with the same limits as hub's key-log page (KEY_LOG_PAGE_*).
- Redeem: per plan 1.7; returns encrypted log + relays (the relay only knows its own public URL → `relays: [publicUrl]`) + rtc config + tenant_id. Push `enroll.redeemed` to all online tenant nodes.
- Password rotation with kick: bump epochs, set min_token_epoch, send `relay.kicked {reason:'password_rotated'}` then close every tenant link whose token_epoch < min.
- Health endpoint cheap and unauthenticated.
- Tests: unit tests per module + an in-process harness `apps/gateway/src/relay/relay-test-harness.ts` exposing: boot relay (memory sqlite), create tenant (root key pair → enroll), fake node client speaking relay/v1 over an in-memory or real WebSocket to exercise auth/status/list/keylog/rtc/relay-stream/quota/kick. Cover: two tenants isolation (list never leaks, relay OPEN across tenants → RST), password kick vs keep, token epoch, member admit root-signed & passkey-tolerated, revoke root-only, seq mismatch, quotas, metering, health/status/admin auth.
