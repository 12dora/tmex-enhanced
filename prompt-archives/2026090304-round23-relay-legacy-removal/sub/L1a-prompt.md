## Background
The WS terminal protocol has a canonical state stream (borsh schemas in packages/shared/src/ws-borsh/canonical-state.ts, spec docs/ws-protocol/2026021402-ws-borsh-v1-spec.md §canonical ~709-747) and a legacy stream (TERM_RESIZE / TERM_SYNC_SIZE / TERM_HISTORY / LIVE_RESUME / STATE_SNAPSHOT / STATE_SNAPSHOT_DIFF / SWITCH_ACK / TERM_OUTPUT / TMUX_FETCH_PANE_HISTORY). The legacy stream will be deleted by other agents in this round (gateway, ws-client/stores, terminal-ui) — you prepare the shared package so they can. Two things block deletion today:
(a) canonical `ResizePane` (canonical-state.ts:116-121) has only pane+rows+cols; legacy kept two kinds because the gateway needs to know whether a size message is a real viewport CHANGE (browser resized) or a RESEND/reconcile of the current size (warm switch, reconnect). See commits 39318f94, 4c7b5274, b220286d (`git show`) and apps/gateway/src/ws/tmux-geometry-handlers.ts:251-280 / apps/gateway/src/ws/viewport-policy.ts for how the gateway consumes it — read-only for you.
(b) canonical clients still receive a legacy STATE_SNAPSHOT "overlay" carrying device-tree order and custom names (packages/ws-client/src/canonical-state-client.ts:248-255 `handleLegacyOverlaySnapshot`, packages/ws-client/src/websocket-transport.ts:207-235, gateway apps/gateway/src/ws/index.ts:342-362). Those fields must become part of the canonical `SourceMetadataRecord`/`SourceMetadataPatch` so the overlay can go away.
