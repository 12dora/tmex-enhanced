## Implementation
1. **Secrets**: mesh_secrets {kind 'log'|'meta', epoch, key_enc (encrypt with the existing master-key helper used for node_identity private keys), created_at}; helpers get/put current K_log, K_meta(epoch), list known meta epochs (keep old epochs so old blobs can still be decrypted for a grace window).
2. **RelayUplinkClient**: same public surface UplinkPool consumes from UplinkClient (status, connect/close, openRelay, inbound relay handler, rtc signal send, node-list callback, enroll.redeemed callback) so the pool can hold either. Flow per plan 1.8/1.9: challenge → `relay.auth` (tenant_id/token from mesh_relays; sig over nonce ‖ relay host; member proof = own admit-node record from the local key log (bytes+sig) — always include it, cheap) → on auth.ok send `relay.status` (blob = sealEnvelope(K_meta, 'status', RelayStatusBlob{name, version, tmux, inventory, endpoints}, epoch)) → handle `relay.list`: for each entry with a blob, open it with the K_meta of that epoch (skip if unknown epoch), require a local admitted node cert for id, then upsert peer_cache exactly like node-list-apply does for hub lists (name/endpoints/inventory/direct/version/online); nodes without blob → online flag only. Key log: compare local head vs `key_log_head_seq` → download missing via `relay.keylog.req` (open each blob with K_log → bytes+sig → apply through the existing KeyLogApplier path with the same fork/ack semantics as uplink-key-log-sync.ts) or upload local records the relay lacks via `relay.keylog.append` (include `member` for admit/revoke records). Local appends (from /api/auth/keylog) must also go out as `relay.keylog.append` — find where UplinkClient forwards `key.log.append` today and mirror. `relay.rtc`: seal/open {sdp, candidate} with current K_meta and bridge to the existing rtc.signal plumbing in mesh-runtime (from/to/rtcSession stay plaintext). `relay.kicked` → mark relay row kicked, emit a mesh event so `/api/mesh/relay/status` shows `reauthRequired`. `relay.quota` → store in memory for status. Relay streams: identical to hub (openRelay / inbound) so PeerManager needs no change.
3. **UplinkPool**: when `node_identity.uplink_kind === 'relay'`, candidates = mesh_relays ordered by priority (no writer/epoch/hub advertisement logic); construct RelayUplinkClient instead of UplinkClient; keep the existing failover/fail-back/probe machinery (probe = GET `/api/relay/health`). Switching kinds at runtime (record applied) must tear down the pool and rebuild — expose `reconfigure()` on mesh-runtime.
4. **Record application** (user-key-persistence / user-key-service): `set-relays` → write mesh_relays (replace all), unwrap own log_key & meta_key entries (node x25519 sk from node_identity) into mesh_secrets, set node_identity.uplink_kind = relays.length ? 'relay' : 'hub', then mesh-runtime.reconfigure(). `meta-key` → unwrap own entry (if absent: keep read-only on old epoch, log warn), store. `rename-node` targeting self → node_identity.name. Ensure the records are also relayed to the relay (they are normal key-log appends).
5. **Tenant-side routes** apps/gateway/src/mesh/relay-routes.ts (node-session auth like other mesh routes): exactly plan 1.9's list: `GET /api/mesh/relay/status`, `POST /api/mesh/relay/enroll/proof-material`, `POST /api/mesh/relay/enroll` (calls the relay's `POST /api/relay/enroll` server-side with fetch; on success returns tenant_id/token AND the unsigned `set-relays` payload bytes: current relays + new one (priority = last+1), log_key/meta_key wrap entries for every non-revoked node cert (x25519_pk from node_certs), generating fresh K_log/K_meta on first enroll — hold generated keys in a pending map keyed by payload hash until the signed record is applied, then persist), `POST /api/mesh/relay/leave/prepare`, `POST /api/mesh/relay/meta-key/prepare` (admit: wrap current K_meta for one node; rotate: new key, new epoch, wrap for all non-revoked minus exclude; pending until applied), `GET /api/mesh/relay/join-material`, `POST /api/mesh/relay/enrollments` (→ `relay.enroll.create` over the current relay uplink, wait for ack ≤10 s) and `GET /api/mesh/relay/enrollments/:id`.
