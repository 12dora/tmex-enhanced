## Task X1 — Frontend performance: agent chat / long conversation history
The product is a web TUI/agent UI (React 19, zustand stores in packages/stores, UI in packages/panels/src/agent, apps/fe/src/pages, packages/ui, markdown renderer in packages/panels/src/markdown). The user's stated concern: like Claude Code, when an agent session's conversation history gets very long (hundreds of messages, big tool-call cards, streaming deltas), scrolling and typing get janky.
Investigate end-to-end: how messages are stored (agent-state.ts, agent-thread.ts, agent-delta-buffer.ts, agent-message-parser.ts, agent-history-sync.ts, agent-persist.ts), how streaming deltas mutate state (do they clone whole arrays / whole session objects per delta? do selectors return new references each time?), how the message list renders (virtualization? memoization? key stability? markdown re-parsing per render? tool-call-card re-render on every delta? syntax highlighting cost?), scroll anchoring / auto-scroll implementation (ResizeObserver, scrollHeight reads causing layout thrash), input box re-renders, and persistence (does every delta write to localStorage/IndexedDB synchronously?). Also check the sidebar session list and any effect that iterates over all sessions/messages on every store change.
Where possible measure: write a bun script in the scratchpad that feeds N=2000 deltas through the real store actions and times them; or count renders with a small test harness. Report the top hot spots with evidence.
