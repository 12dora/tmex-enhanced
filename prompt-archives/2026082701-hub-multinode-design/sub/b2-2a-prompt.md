## Context

This task is the node-side **transport plane**: connecting to the hub, talking to peers over links, and terminating `http` / `ws` streams into the local gateway. The HTTP surface (`/api/auth/*`, `/api/mesh/*`, `/n/:id/*` forwarding, login) is a separate concurrent task (B2-2b) that will consume your `PeerManager` — so your public API must be clean and documented in the report.

## Deliverables (`apps/gateway/src/mesh/`)

1. **`uplink-client.ts`** — `UplinkClient({hubUrl, identity: {nodeId, edSecretKey}, userId, keyLogApplier, userStore, statusProvider: () => NodeStatus, onNodeList(list), onRtcSignal(msg), onEnrollRedeemed(msg), wsFactory?})`: connects `wss://<hub>/hub/uplink` (Bun `WebSocket` → `WebSocketLink` initiator), exponential backoff 1 s → 60 s with jitter, performs `auth.challenge/response`, sends `node.status` on connect and whenever `statusProvider` output changes (`sendStatus()`), heartbeat `ping` every 15 s, 3 missed `pong` → reconnect; `node.list` → upsert `peer_cache` (metadata only) and, if `key_log_head.seq` > local head, `key.log.req` → `applyMany`; exposes `link: LinkSession | null`, `state: 'offline'|'connecting'|'online'`, `onStateChange`, `sendCtl(msg)`, `openRelay(toNodeId): Promise<LinkStream>` (opens a `relay` stream with OPEN payload `{to}`), `stop()`.
2. **`peer-protocol.ts`** — peer-port signaling over plain WS (`WebSocketLink`): first ctl exchange is the handshake: `hello {node_id, nonce, eph_x25519_pk}` both ways → `transcript = buildPeerTranscript('relay' | 'dc', ...)` → `sig` → `verifyTranscript` with the peer's `ed_pk` from `node_certs` (unknown/revoked → close). For the **direct WebSocket peer link (path 1)** we run the same `LinkMux` over the WS after the handshake without extra encryption (the design says path 1's data plane is WebRTC; until Phase 3 lands, path 1 = signaling WS carrying the mux directly — mark this clearly as `transport: 'ws-direct'` and keep the `DataChannelLink` slot typed so B3-1 can drop in). For **relay (path 3)**: after obtaining a relay stream from `UplinkClient.openRelay`, run the same handshake as ctl JSON lines over the raw stream, derive keys with `derivePeerSessionKeys`, wrap with `SecureChannelLink`, then `LinkMux` on top. Initiator/acceptor roles: initiator = the side that opened the connection.
3. **`peer-server.ts`** — Bun `Bun.serve` on `TMEX_PEER_PORT` (bind `0.0.0.0` and `::` — check what Bun supports; if dual-stack needs two servers, do that) accepting `/peer` WS upgrades only; per-source-IP rate limit (10 handshakes/min); hands accepted links to `PeerManager`. Inbound relay streams arriving on the uplink (`onStream` with OPEN `{to: self, from}`) are also handed to `PeerManager` as acceptor.
4. **`peer-manager.ts`** — `PeerManager({identity, userStore, uplink, peerPort, now?})`: `getLink(nodeId): Promise<LinkSession>` — reuse an existing live link; else try `peer_cache.endpoints_json` addresses in order (`ws://host:port/peer`) with a short connect timeout; else relay via hub; all fail → throw `NodeUnreachableError`. Idle links (no streams for 5 min) closed. ctl on peer links: `ping/pong`, `node.status` (exchange endpoints/inventory/`key_log_head` and update `peer_cache`), `key.log.req/res` (peer catch-up when hub is down). `onRevoked(nodeId)` closes links and deletes `peer_cache`. `listReach(): Map<nodeId, 'lan'|'relay'|null>`. `stop()`.
5. **Stream terminations (`stream-targets.ts`)** — acceptor side of `http` and `ws` streams as defined in §3 "流类型", invoked for streams opened on any peer link (direct or relay):
   - `http`: OPEN payload JSON `{method, path, query, headers, origin, auth}`; verify `auth` via `NodeSessionStore.verify(sid, {viaNodeId: link peer id})` (skip for `/api/auth/challenge|login`); build a `Request` with a `ReadableStream` body fed from DATA frames (END → close body), `signal` aborted on RST; call `dispatchHttp(request, {uid})`; write response: first DATA with `head` flag = JSON `{status, headers}`, then body chunks, then END; if the response finishes before the request body is consumed, send RST on the request direction per design; on response stream cancel → RST.
   - `ws`: OPEN `{auth}` verified the same way → `LinkStreamCarrier` (implements `Carrier`: DATA frames in → gateway messages; `send()` → `stream.write` with a bounded internal queue mapping to `'backpressure'` when > 1 MiB unflushed and `onDrain` when it falls below; `close/terminate` → END/RST) → `WebSocketServer.attachStreamSession(carrier)`.
   - Entry side helpers used by B2-2b: `openHttpStream(link, openPayload, body?, signal) → Promise<Response>` and `openWsStream(link, auth) → {stream, …}`; put these here so both directions are tested together.
6. **`runtime.ts`**: add `dispatchHttp(request: Request, ctx: {uid: string}): Promise<Response>` on `GatewayRuntime` — reuses the existing API route table without any Bun `Server`; make `ApiRouteContext.server` optional (fix the few handlers that type it). Unknown `/api/*` → 404 like `handleRequest`. Nothing else in runtime.ts.
7. **Tests**: uplink auth + backoff (fake WS factory) + status/heartbeat + node.list → peer_cache + key.log catch-up via injected applier; peer handshake happy / wrong key / revoked / tampered transcript; relay path derives the same keys on both ends and carries a mux stream; PeerManager reuse/fallback order/idle close/unreachable; `http` stream round-trip against a real `GatewayRuntime.dispatchHttp` (use whatever existing runtime test fixture exists, e.g. in `apps/gateway/src/api/*.test.ts`, or a minimal route) including body streaming, abort→RST, early response→RST; `ws` stream → HELLO round-trip through `attachStreamSession` with a fake session; `LinkStreamCarrier` backpressure/drain.
