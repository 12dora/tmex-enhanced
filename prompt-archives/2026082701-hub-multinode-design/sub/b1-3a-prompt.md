# Task B1-3a — shared identity primitives (packages/shared/src/auth/)

## Context

tmex is adding a hub/node mesh where the user's identity is a self-held key pair: a password-derived Ed25519 "root key" plus optional passkeys. All machines store only public keys. You are implementing the **pure, browser+Bun shared** crypto/encoding layer in a new module `packages/shared/src/auth/`. No database, no HTTP, no cookies — that is a separate task (`apps/gateway/src/auth/`) which will import your module, so your exported API must be complete and precisely typed.

Read `docs/hub/2026082700-hub-node-architecture.md` §2 fully (sections "规范编码", "用户密钥", "令牌与信任矩阵", "登录", "node 注册与节点证书", "链路身份与握手") — every domain string, field, and rule below comes from there; the design doc wins if this prompt is ambiguous. Then read `prompt-archives/2026082701-hub-multinode-design/sub/e0-4-result.md` §1, §2, §5 for verified library APIs.

Libraries (installed in `packages/shared`, verified in Bun 1.3.14): `hash-wasm@4.12.0` (`argon2id({password, salt, parallelism, iterations, memorySize, hashLength, outputType:'binary'})` — `validateOptions` mutates the options object, so build a fresh object per call), `@noble/curves@2.3.0` and `@noble/hashes@2.3.0` (ESM-only, import via `.js` subpaths: `@noble/curves/ed25519.js` exports `ed25519`, `x25519`; `@noble/hashes/hkdf.js`, `@noble/hashes/sha2.js`, `@noble/hashes/utils.js`), `@zorsh/zorsh@0.4.0` (`b.struct/b.string/b.u32/b.u64(bigint)/b.bytes(N)/b.bytes()/b.enum/b.option/b.vec`; see existing usage in `packages/shared/src/ws-borsh/schema.ts`). Browser code must not depend on `crypto.subtle` (login must work on `http://<LAN-IP>`, a non-secure context) — use noble for HKDF/SHA-256; the only WebCrypto use allowed is `crypto.getRandomValues`. AES-GCM for TOTP: node side (Bun) may use `crypto.subtle`; put the AES helper in its own file and make the browser-side TOTP path only need `k_totp` derivation (HKDF via noble).

Verified Argon2id vector (hash-wasm on Bun 1.3.14 == independent implementation): `password="tmex-test"`, `salt=16×0x01`, `m=65536 KiB, t=3, p=1, len=32` → `c309e52473a3209eb21f065c873725f397a79dc8de84d30b078f95c2a3ae8c85`. Lock it in a test.

## Deliverables (one file per concern, `index.ts` barrel; add `"./auth": "./src/auth/index.ts"` to `packages/shared/package.json` `exports`; do NOT export from the main `src/index.ts`)

1. `encoding.ts` — Borsh schemas for every signed object, each with `domain` as the first field, plus `encode*/decode*` helpers and `sha256(bytes)`, base64url encode/decode, hex helpers, `randomBytes(n)`. Objects and their domains: `delegation` (`tmex/delegation/v1`: `uid, sess_pk[32], issued_at u64, exp u64, method enum{root,passkey}, credential_id option<string>`), `login` (`tmex/login/v1`: `challenge_id, nonce[32], target, target_pk[32], uid, entry`), `authorization` (`tmex/enroll/v1`: `uid, enroll_pk[32], exp u64, root_epoch u32`), `certificate` (`tmex/nodecert/v1`: `uid, node_id[16], ed_pk[32], x25519_pk[32], enroll_pk[32], issued_at u64`), `keyLogRecord` (`tmex/keylog/v1`: `uid, seq u64, prev_hash[32], root_epoch u32, type enum{add-passkey, remove-passkey, rotate-root, set-totp, clear-totp, admit-node, revoke-node, reset-root}, payload bytes, signer enum{root,passkey}, credential_id option<string>`), `peerTranscript` (`tmex/peer/v1`: `path enum{dc,relay}, hello_lo, hello_hi` where `hello = {node_id, nonce[32], eph_x25519_pk option<[32]>, dtls_fingerprint option<{algorithm string, value string}>}` and lo/hi are ordered by `node_id` lexicographically), `totpAad` (`{uid, root_epoch u32, seq u64}`). Also typed payload schemas for the key-log record types: `add-passkey` (`credential_id, public_key bytes(COSE), rp_id, origin, counter u32, transports vec<string>, backup_eligible bool, backup_state bool, device_type string, name string`), `remove-passkey` (`credential_id`), `rotate-root` / `reset-root` (`root_public_key[32], kdf_params {salt[16], memory_kib u32, iterations u32, parallelism u32}`), `set-totp` (`alg string, nonce[12], ciphertext bytes, tag[16]`), `clear-totp` (empty), `admit-node` (`authorization_bytes, authorization_sig[64], certificate_bytes, cert_sig[64]`), `revoke-node` (`node_id[16], reason string`). Enum variant order is wire format — fix it as listed and never reorder.
2. `root-key.ts` — `deriveSeed(password, kdfParams)` (NFKC normalize → UTF-8 → argon2id with the fixed parameters `m=65536,t=3,p=1,len=32`, salt from params), `rootKeyFromSeed(seed) → { publicKey, sign(msg), seed }`, `generateKdfParams()` (random 16-byte salt), Ed25519 `sign/verify` wrappers (strict RFC 8032: pass `{ zip215: false }` to verify), `generateEd25519KeyPair()`, `generateX25519KeyPair()`.
3. `delegation.ts` — `createDelegation(rootKey, {uid, sessPk, now})` (exp = issued_at + 18 h), `verifyDelegation(delegation, sig, {rootPublicKey, now})` for `method=root`; for `method=passkey` export `delegationChallenge(delegation) = sha256(borsh(delegation))` and a `verifyDelegationPasskey` hook type that the gateway fills with SimpleWebAuthn (you only provide the challenge computation and the shape).
4. `login.ts` — `buildLogin(...)`, `signLogin(sessSk, login)`, `verifyLogin(login, sig, sessPk, expected: {challengeId, nonce, target, targetPk, uid, entry})` returning a discriminated result with a precise error code (`challenge_mismatch | target_mismatch | uid_mismatch | entry_mismatch | bad_signature`).
5. `key-log.ts` — pure chain logic: `computeRecordHash(recordBytes, sig) = sha256(recordBytes ‖ sig)`, `KeyLogHead = {seq: bigint, hash: Uint8Array(32)}` (genesis: seq 0, hash = 32 zero bytes), `buildKeyLogRecord(head, epoch, {uid, type, payload, signer, credential_id})`, `signKeyLogRecordWithRoot(rootKey, recordBytes)`, `verifyKeyLogRecord(recordBytes, sig, ctx: {head, rootEpoch, rootPublicKey, resolvePasskey(credentialId) → COSE key | null, verifyPasskeyAssertion?})` returning `{ok, record, hash} | {ok:false, error: 'seq_gap' | 'prev_hash_mismatch' | 'epoch_mismatch' | 'bad_signature' | 'unknown_signer' | 'fork'}` — `fork` is detected by a helper `detectFork(existingRecordAtSeq, incomingRecord)`; `applyKeyLogRecord(state, record)` as a pure reducer over an in-memory `UserKeyState = {rootPublicKey, rootEpoch, kdfParams, passkeys: Map, totp: record | null, nodeCerts: Map<nodeIdHex, {...}>, head}` that implements: `rotate-root`/`reset-root` → new root pk + kdf params, `rootEpoch += 1`, clear passkeys and totp (node-session revocation is the gateway's job — expose it as a returned `effects` list: `revokeAllSessions`, `revokeSessionsByCredential(id)`, `revokeSessionsVia(nodeId)`); `add-passkey`/`remove-passkey`; `set-totp`/`clear-totp`; `admit-node` (verify chain: `authorization_sig` by root pk of the record's epoch, `cert_sig` by `authorization.enroll_pk`, `certificate.enroll_pk == authorization.enroll_pk`, `authorization.uid == certificate.uid == record.uid`; on success store cert) ; `revoke-node` (mark revoked). `verifyKeyLogChain(records: {bytes, sig}[], trustedRootPublicKey, expectedHeadHash?)` walks from genesis applying the reducer and switching the verification key on `rotate-root` — used by `hub join`.
6. `enrollment.ts` — `createEnrollment(rootKey|passkeySigner, {uid, rootEpoch, now, ttlMs=10min}) → {enrollSk, enrollPk, authorizationBytes, authorizationSig}`, `encodeJoinToken(enrollSk, rootPublicKey, keyLogHeadHash) → base64url (96 bytes → 128 chars)` / `decodeJoinToken`, `createNodeCertificate(enrollSk, {uid, edPk, x25519Pk, enrollPk, now}) → {nodeId(16 random), certificateBytes, certSig}`, `verifyNodeCertificate(certBytes, certSig, enrollPk)`.
7. `totp.ts` — `deriveTotpKey(seed, uid, rootEpoch) = HKDF-SHA-256(seed, salt = "tmex-totp" ‖ u32LE(rootEpoch), info = uid, 32)` (noble hkdf, browser-safe); `totpCode(secret, time, {step=30, digits=6})` RFC 6238 HMAC-SHA1 (noble `@noble/hashes/sha1.js` — verify it exists; else `legacy.js`) with ±1 step tolerance helper `verifyTotpCode`; test with the RFC 6238 vectors. `totp-cipher.ts` (WebCrypto AES-256-GCM, node side): `encryptTotpSecret(kTotp, secret, aad) → {alg:'A256GCM', nonce, ciphertext, tag}`, `decryptTotpSecret(kTotp, record, aad)`; AAD = `borsh(totpAad)`.
8. `peer-handshake.ts` — `buildPeerTranscript(path, helloA, helloB)` (sorts by node_id), `signTranscript(nodeEdSk, transcript)`, `verifyTranscript(...)`, `normalizeFingerprint({algorithm, value})` → lowercase algorithm, uppercase hex without colons, `parseSdpFingerprint(sdp)`. Session keys: export `derivePeerSessionKeys(sharedSecret, transcriptBytes, selfNodeId, peerNodeId) → {sendKey, recvKey}` with `k = HKDF-SHA-256(ss, salt = sha256(transcript), info = "tmex-sc/v1/" ‖ sender ‖ "->" ‖ receiver, 32)` (sender/receiver are node_id hex strings, UTF-8). NOTE: another agent is concurrently writing `packages/shared/src/link/secure-channel-link.ts` with a function of the same key schedule; do not import it — just implement it here and add a fixed test vector (document the exact input bytes) so the coordinator can cross-check both.
9. `index.ts` barrel + `README` is NOT needed.
