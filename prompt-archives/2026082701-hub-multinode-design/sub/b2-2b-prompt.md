## Deliverables (`apps/gateway/src/mesh/`)

1. **`auth-routes.ts`** — handlers for the local node (`self`):
   - `GET /api/auth/mode` → `{mode:'none'|'mesh', nodeId, username, kdfParams, passkeysForThisOrigin, passkeyAvailable}` (`mode:'none'` when `TMEX_ROLES` = standalone; `passkeysForThisOrigin` = any `user_keys` row whose `origin` equals the request origin).
   - `POST /api/auth/challenge {uid}` → `ChallengeStore.create({kind:'login', uid, entryNodeId})` where `entryNodeId` = `'self'` for a local Bun request or the peer node id when the request arrived via an `http` stream (the stream terminator passes it in a request header `x-tmex-via` that you strip/verify is only settable internally — define the convention: the assembler sets `ctx.via` on the `Request` via a `WeakMap<Request, {via}>` exported from `mesh-deps.ts`; never trust a client-supplied header). Returns `{challenge_id, nonce(b64url), nodePk(b64url)}`.
   - `POST /api/auth/login {login, sig, delegation, delegation_sig, totp?}` implementing §2 step 3 exactly in that order with precise error codes; TOTP check derived from `delegation.method`; on success `NodeSessionStore.issue` and `Set-Cookie: tmex_s_<T>` (T = `self` when local, else this node's id — the entry rewrites? No: per design the **entry** sets the cookie for its own origin; so the login response carries `{sid, expires_at}` in JSON and a `x-tmex-set-session: <sid>;<max-age>` header; the forwarder (item 4) turns it into `Set-Cookie tmex_s_<nodeId>` on the entry origin; for `self` you set the cookie directly). Rate limit: 10 failures / minute per uid and per ip → 429.
   - `POST /api/auth/logout` → revoke all sessions for the uid of the presented session; clear cookie.
   - Passkey ceremony: `POST /api/auth/passkey/register/options` (requires a valid node-session; `ChallengeStore` kind `passkey-register`, 60 s) and `POST /api/auth/passkey/register/verify {response}` → returns the `AddPasskeyPayload` fields for the browser to sign into an `add-passkey` record (this route does NOT write the record); `POST /api/auth/passkey/login/options {uid, delegation}` → `createAuthenticationOptions` with `challenge = delegationChallenge(delegation)`.
   - `POST /api/auth/keylog {bytes, sig}` (b64url; requires node-session) → `UserKeyService.apply`; on success also forward to hub via an injected `KeyLogPublisher.publish(record)` (B2-1's `key.log.append`) — interface in `mesh-deps.ts`; fork → 409 `{code:'KEY_LOG_FORK'}`.
2. **`session-middleware.ts`** — `authenticateRequest(req, {via}) → {ok:true, userId, session, renewedExpiresAt?} | {ok:false}` reading cookie `tmex_s_self` (local) or the `auth` sid supplied by the stream terminator; applies `x-tmex-session-renewed` on the response. `requireSession(handler)` wrapper. Standalone bypass: when roles = standalone, every request passes with `uid = null` and no login page.
3. **`mesh-routes.ts`** — `GET /api/mesh/nodes` (merge `node_certs` public keys, `peer_cache` metadata, live reach from `PeerLinkProvider.listReach()`, `loggedIn` = whether a `tmex_s_<id>` cookie is present on the request; exclude non-admitted/revoked; include `self`), `GET /api/mesh/rtc-config` (from `peer_cache` last `node.list`), `POST /api/rtc/authorize {rtcSession, fp_browser}` (requires session; `ChallengeStore` kind `rtc-authorize` 2 min; returns `{nonce, fp_node}` where `fp_node` comes from an injected `RtcFingerprintProvider` — Phase 3 fills it; until then return 503 `DIRECT_UNAVAILABLE` when absent), `GET /mesh/ws` upgrade (requires `tmex_s_self`): a plain Bun WebSocket carrying Borsh `NODE_EVENT` (from `PeerLinkProvider.onNodeEvent`) and `RTC_SIGNAL` relay (to/from an injected `RtcSignalRouter` — Phase 3). Use the kinds/schemas B2-1 is adding to `packages/shared/src/ws-borsh` (`NODE_EVENT`, `RTC_SIGNAL`); if they are not there yet when you start, write against the names in `sub/b2-1-prompt.md` and re-check before finishing.
4. **`forwarder.ts`** — `/n/:id/api/*` and `/n/:id/ws`: `self` → rewrite to local path and fall through to the gateway (return `null` so the assembler continues the chain) ; otherwise `PeerLinkProvider.getLink(id)` (unreachable → 503 `{code:'NODE_UNREACHABLE'}`), strip prefix, filter request headers per §3 (`cookie/authorization/host/connection/upgrade/proxy-*/x-forwarded-*`), `auth` = sid from cookie `tmex_s_<id>` (null for `/api/auth/challenge|login`), stream the body, abort → RST via `signal`; response: **header allowlist + forced CSP sandbox + nosniff + MIME allowlist with octet-stream/attachment override** exactly as §3 "响应头策略"; 401 from target → pass through with JSON body augmented `{code:'NODE_LOGIN_REQUIRED', nodeId}`; login success (`x-tmex-set-session`) → `Set-Cookie tmex_s_<id>` on the entry origin (HttpOnly, SameSite=Lax, Path=/, Max-Age, Secure if https); `x-tmex-session-renewed` → refresh cookie Max-Age. `/n/:id/ws` → Bun upgrade, then `openWsStream` and pump both ways (browser frames → stream, stream → browser), close codes propagate (4401 when auth fails).
5. **`mesh-http.ts`** — `MeshHttpRuntime({roles, nodeId, userStore, keyLogService, challengeStore, nodeSessionStore, peers, streams, publisher, rtc?})` with `handleRequest(req, server): Promise<Response | null>` implementing the §3 "entry 侧路由" order for the paths above and `handleWebSocket` callbacks for `/mesh/ws` and `/n/:id/ws` sockets; and `localUiGuard(req) → Response | null` that the assembler runs before gateway routes (401 JSON for `/api/*`, redirect-free — the SPA handles `/login`; static assets and `/login` itself always pass).
6. **Tests** (`mesh/*.test.ts`, `test-db.ts`, fake `PeerLinkProvider`/`StreamOpener`): full login happy path with a real `bootstrapUser` + browser-side objects built with `@tmex/shared/auth` (delegation by root, login by sess key), each failure code (consumed challenge, wrong entry, wrong target_pk, expired delegation, bad sig, wrong TOTP), rate limit, logout, session renewal header, `mode`, `/api/mesh/nodes` merge, forwarder header filtering + response policy (SVG → octet-stream attachment, HTML → same, PNG passes, unknown header dropped, CSP present), 401 augmentation, cookie set on login via forwarder, `self` fallthrough, unreachable 503, `/n/:id/ws` pump with a fake stream, standalone bypass.
