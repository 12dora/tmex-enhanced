## Deliverables (all in `apps/gateway/src/auth/`, extend the existing barrel)

1. **`key-log-store.ts`** — `KeyLogStore(db)` persisting `user_key_log` (`record_bytes`, `sig`, `hash`, `prev_hash`, `seq`, `root_epoch`, `type`, `payload_json` projection built from the decoded payload, `created_at`): `head(userId) → KeyLogHead` (from `users.key_log_head_*`), `list(userId, fromSeq?) → {bytes, sig, seq, hash}[]`, `getAtSeq(userId, seq)`.
2. **`user-key-service.ts`** — `UserKeyService({db, userStore, keyLogStore, nodeSessionStore, verifyPasskeyAssertion})`, the single entry point that **applies** a key-log record to this node's DB inside one SQLite transaction:
   - `apply(userId, {bytes, sig}) → {ok:true, seq, hash, effects} | {ok:false, error}`: load current `UserKeyState` from DB (root pk/epoch/kdf from `users`, passkeys from `user_keys`, totp from `users.totp_record_seq` → record payload, node certs from `node_certs`, head), call `verifyKeyLogRecord` (pass `existingAtSeq` from `getAtSeq` so forks are detected — a fork must be reported as `{ok:false, error:'fork'}` and **must not** modify the DB; also surface it so the UI can show "密钥日志分叉"), then `applyKeyLogRecord`, then persist the diff: users (root pk / epoch / kdf / head / totp seq), `user_keys` insert/delete (`log_seq` = this record's seq), `node_certs` upsert/`markCertRevoked`, and execute `effects` against `NodeSessionStore` (`revokeAllSessions` → `revokeAllForUser`; `revokeSessionsByCredential`; `revokeSessionsVia(nodeId)` → `revokeVia(nodeIdHex)`), plus on `revoke-node` delete that node from `peer_cache`.
   - `applyMany(userId, records)` for catch-up from hub/peer (`key.log`), stopping at the first failure and reporting how many applied.
   - `bootstrapUser({username, password}) → {userId, rootPublicKey, rootEpoch}`: used by `hub user add` and `mesh reset-root`. Derives the root key (`generateKdfParams` + `deriveSeed` + `rootKeyFromSeed`), builds and self-signs the genesis `reset-root` record (seq 1, `root_epoch` = current users.root_epoch if the user exists else 0), creates/updates the `users` row, **wipes** `user_key_log`, `user_keys`, `node_sessions` for that user and clears totp, then applies the genesis record through `apply`. Returns the `RootKey` too (caller may need to sign `admit-node` right after; never persist it).
   - `signAndApply(userId, rootKey, {type, payload})`: build next record (`buildKeyLogRecord` from head + current epoch), sign with root, `apply`. Used by CLI flows (`hub user passwd` → `rotate-root`, `hub user totp` → `set-totp`, `enroll` → `admit-node`).
   - `currentState(userId) → UserKeyState` (read-only projection) and `verifyChainForJoin(records, expectedRootPublicKey, expectedHeadHash)` wrapping `verifyKeyLogChain`, then persisting the whole verified chain (used by `hub join`; the DB must be empty for that user or this must refuse).
3. **`passkey.ts`** — SimpleWebAuthn glue: `createRegistrationOptions({uid, userId, rpId, existingCredentialIds, challenge})`, `verifyRegistration({response, expectedChallenge, origin, rpId}) → AddPasskeyPayload fields (+ counter, transports, backup flags, device type)`, `createAuthenticationOptions({rpId, allowCredentials, challenge})`, `verifyAssertion({response, expectedChallenge, origin, rpId, credential: {id, publicKey(COSE), counter, transports}}) → {ok, newCounter, userVerified}` implementing the design's counter rule (stored counter non-zero and new ≤ stored → reject; stored zero → skip). Export two adapters matching the shared types: `makeVerifyPasskeyAssertion(userStore)` (for key-log records: challenge = sha256(recordBytes), assertion JSON in `sig`? — decide the encoding of a passkey-signed record's `sig`: it must be bytes; use UTF-8 JSON of the `AuthenticationResponseJSON`, document it) and `makeVerifyDelegationPasskey(userStore)` (challenge = `delegationChallenge(delegation)`). Origin/rpId for verification come from the stored `user_keys` row for that credential (design: each credential is bound to its registration origin).
4. **`node-identity-service.ts`** — `ensureNodeIdentity(store, {hubUrl?}) → identity`: load or generate Ed25519 + X25519 key pairs and a random 16-byte node id, persist via `NodeIdentityStore`; `selfSignedNodeCertificate(identity, rootKey, {uid, rootEpoch, now})`: for the hub machine / reset-root path — create an enrollment with the root key, create the node certificate with `enrollSk`, and return the `admit-node` payload ready for `signAndApply`.
5. **Tests** using `test-db.ts`: bootstrap → genesis applied, state matches; `signAndApply` rotate-root revokes all sessions, clears passkeys and totp, bumps epoch, then a record signed by the old root is rejected; fork: applying a different record at an existing seq → `fork`, DB unchanged; admit-node stores cert, revoke-node marks it revoked + `revokeVia` + `peer_cache` delete; `verifyChainForJoin` with a chain produced by `bootstrapUser` + two records on another in-memory DB → persisted identically (same head hash); passkey: registration/verification round-trip using a synthetic authenticator — if `@simplewebauthn/server` ships test helpers use them, otherwise craft a minimal ES256 credential with WebCrypto (`crypto.subtle` P-256) producing valid `authenticatorData/clientDataJSON/signature` — do not skip this test; counter rule; node identity ensure → stable across loads, self-signed cert verifies through `applyKeyLogRecord`.
