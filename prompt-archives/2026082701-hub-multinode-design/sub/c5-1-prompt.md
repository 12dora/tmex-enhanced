## Deliverables

1. **Nested command dispatch** in `packages/app/src/cli/args.ts` (or wherever `parseArgs` lives): `hub user add <username>`, `hub user passwd <username>`, `hub user totp <username>`, `hub user reset`, `hub join <https-url> --token <t> [--name <n>]`, `hub leave`, `mesh reset-root`, `enroll [--ttl 10m]`, `direct enable|disable` (only parse it; implementation belongs to C5-2 — dispatch to a stub module `commands/direct.ts` that C5-2 owns, so create only the dispatch line and ask the coordinator to merge if the file does not exist yet), `init --role standalone|node|hub,node`. Keep existing commands and `--help` output consistent.
2. **Password prompting**: hidden TTY input with confirmation for `add`/`passwd`/`reset-root`; reject empty; NFKC handled by the shared `deriveSeed`. Non-TTY → read from `TMEX_PASSWORD` env for scripts/tests, documented.
3. `hub user add`: `bootstrapUser` → then `ensureNodeIdentity` → `selfSignedNodeCertificate` → `signAndApply(admit-node)` (hub machine is the first node; no join). Print root public key fingerprint. `hub user passwd`: derive old root key from the old password (verify it matches `users.root_public_key`), new password → new kdf params + key, `signAndApply('rotate-root')` signed by the OLD key; print the warning about passkeys/TOTP reset. `hub user totp`: generate 20-byte secret, `deriveTotpKey`, `encryptTotpSecret`, `signAndApply('set-totp')`; print otpauth URI (+ ASCII QR only if a dependency already exists; otherwise the URI). `hub user reset` (hub machine): wipe `nodes`/`enrollment_tokens` for the user. `mesh reset-root`: `bootstrapUser` on the existing username (keeps username), then re-self-sign this machine's `admit-node`; refuse if `TMEX_ROLES` is standalone.
4. `enroll [--ttl]`: prompt password → `createEnrollment(rootKey)` → `POST <hubUrl>/api/hub/enrollments` **through the local node's own API is not possible from the CLI without a session**, so the CLI signs and calls the hub directly with a node-session obtained how? — design says the enrollment is created "经 entry 的 hub.call"; for the CLI implement: (a) if `TMEX_ROLES` includes hub, insert the `enrollment_tokens` row directly into the local DB; (b) else POST to `TMEX_HUB_URL` `/api/hub/enrollments` — this needs auth; add a CLI-only path: the CLI performs the browser login flow itself (challenge/login with a delegation signed by the root key it just derived, against `TMEX_HUB_URL` + `/n/<hubNodeId>/api/auth/*`… that requires the mesh HTTP surface). Decide: implement (a) fully and for (b) implement the login-based path against the contract in `sub/b2-2b-prompt.md` / `sub/b2-2b-result.md` (whichever exists), isolated in `lib/hub-client.ts` so it can be adjusted. Print the join token (128 chars) and the full `npx tmex-cli hub join <url> --token <t>` command; then wait (poll the hub `GET /api/hub/nodes` or, for hub machines, the local `nodes` table) until a node with this `enroll_pk` appears, then sign `admit-node` via `signAndApply` — Ctrl-C exits and prints "confirm in the Nodes page".
5. `hub join <https-url> --token`: URL must be `https:` (Bun `fetch` validates the system trust chain by default; reject `http:`; allow `http://127.0.0.1`/`localhost` only with `--insecure-local` for tests). `decodeJoinToken` → `ensureNodeIdentity` → `createNodeCertificate(enrollSk, …)` → `POST /api/hub/enrollments/redeem` → response `{user, user_key_log, node_certs}` → `verifyChainForJoin(records, rootPublicKey from token, keyLogHeadHash from token)` (must match), persist node certs via the service, write `TMEX_HUB_URL`, `TMEX_ROLES=node` (unless already `hub,node`) to `app.env` via the layout helpers, save `hub_url` in `node_identity`, then restart the service (`service.ts` restart). `hub leave`: clear `node_identity.hub_url`, set roles back to standalone in `app.env`, restart.
6. `init --role`: `InitConfig.role`; `buildAppEnvValues` writes `TMEX_ROLES`, `TMEX_HUB_URL` (empty allowed), `TMEX_PEER_PORT`, `TMEX_HUB_PUBLIC_URL` (hub only, prompt), `TMEX_STUN_SERVERS` default `stun:stun.l.google.com:19302`; `upgrade` must **preserve** existing `app.env` and add missing keys with defaults (it currently does not rewrite app.env — add a merge step that only appends missing keys). `run.sh` unchanged unless a variable must be forced.
7. Tests (`packages/app` `bun test`): args nested dispatch + help; `app.env` new keys + upgrade merge; `hub user add` end-to-end on a temp DB (genesis + admit-node present, `node_identity` created); `passwd` rotate-root chain valid + old password rejected; `totp` record decrypts with `deriveTotpKey`; `mesh reset-root` bumps epoch and clears certs; `hub join` against a fake hub server (Bun.serve on 127.0.0.1 with `--insecure-local`) using fixtures produced by `UserKeyService` in another temp DB: chain verified, root mismatch rejected, http rejected; `enroll` path (a) creates a token and admits after a fake redeem.
