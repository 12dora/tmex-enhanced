Fix each, with a regression test that fails before / passes after:

1. **Revoke requires a signed record**: `POST /api/hub/nodes/:id/revoke {bytes, sig}` (a user-signed `revoke-node` record) → `keyLogSource.append` → only on success and only for the `revokeSessionsVia`/revoked node from the record's payload: set `nodes.status='revoked'`, disconnect uplink, drop RTC registrations, broadcast. No session-only revoke path remains. Rename endpoint body accordingly and document.
2. **`HubKeyLogSource` contract**: `append` MUST be the real validating apply. Change the interface to return `{ok:true, seq, hash, effects: KeyLogEffect[], record: {type, payload}}` and make hub tests use a real `UserKeyService` over `test-db.ts` (build records with `@tmex/shared/auth`), deleting the random-bytes fake. Add tests: forged `admit-node`, `revoke-node`, `rotate-root` (wrong key / wrong seq / wrong epoch) must fail and not advance the head; a valid `revoke-node` via `key.log.append` from a node disconnects the revoked node and refuses its reconnect.
3. **Redeem transaction + epoch**: consume token and `createNode` inside one `db.transaction`; before consuming, load the user and require `authorization.root_epoch === user.rootEpoch` (else 400 `epoch_mismatch`); on `rotate-root`/`reset-root` effects (from item 2), invalidate all unused enrollment tokens of that user (`UserStore` method; add it — `src/auth/user-store.ts` is in scope for that single method).
4. **Passkey enrollment authorization**: `POST /api/hub/enrollments`: decode authorization; `signer='root'` → 64-byte Ed25519 with current root pk; `signer='passkey'` → `PasskeyAssertion` bytes verified via `makeVerifyPasskeyAssertion(userStore)` with challenge `sha256(authorization_bytes)`; test both.
5. **Revocation effects on live state**: after any successful append, apply `effects`: `revokeSessionsVia(nodeId)` → mark `nodes.status='revoked'`, close its uplink, remove RTC registrations, broadcast; every ctl handler and `onIncomingStream` re-checks that the live identity's cert is still non-revoked.
6. **Relay isolation**: initiator user = `live.userId` (from the authenticated cert), target must have a non-revoked `node_certs` row with the same `userId`, and `nodes.userId` is never used for authorization.
7. **RTC registrations**: `registerRtcSession({rtcSession: server-generated random id, userId, browserSessionId, fromNodeId, toNodeId, ttlMs=2min})`, forward only when both nodes belong to `userId`, delete on forward-complete/TTL/either link close; bound the map.
8. **Auth timeout + stop**: track all accepted links; 10 s auth deadline timer; `stop()` closes unauthenticated links too; timers cleared on auth/close/replace.
9. **Heartbeat**: only a `pong` matching an outstanding ping resets misses; close when `misses >= limit`.
10. **Per-link ctl serialization**: promise chain per link so ctl frames are processed in order; a handler throw closes the link with a reason.
11. **Hostile ctl bounds**: max ctl frame 64 KiB, JSON depth ≤ 8, arrays ≤ 1024, strings ≤ 4 KiB (endpoints ≤ 32 entries), `seq` strictly u64 (safe integer or ≤ 20-digit string ≤ 2^64-1); violations close the link (`protocol_error`). Tests with oversized `inventory`, deep JSON, bad seq.
