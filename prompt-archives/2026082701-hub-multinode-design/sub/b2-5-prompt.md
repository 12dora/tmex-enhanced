## Deliverables (each with tests)

1. `GET /api/auth/keylog/head` → `{seq, hash(b64url), rootEpoch}` (session required). `GET /api/auth/passkeys` → `{passkeys:[{credential_id, name, rp_id, origin, created_at, log_seq}]}`. `GET /api/auth/mode` adds `rootEpoch`, `rootPublicKey` (b64url), `hubNodeId` (this node's id when `roles.hub`, else the hub node id learned from `node.list` if the hub marks itself — see 3), `hubPublicUrl` (from `node.list` / config).
2. `node.list` (hub → nodes) gains `hub: {nodeId, publicUrl}`; nodes persist it (`peer_cache` row for the hub node gets a flag, or a small `mesh_meta` KV in `peer_cache` with node_id `hub` — choose the simplest that survives restart) so `/api/mesh/nodes` can add `isHub: boolean` and `/api/auth/mode` can answer offline. `POST /n/<hub>/api/hub/enrollments` response adds `public_url` and `id`.
3. Redeemed certificate delivery: hub stores `{certificate_b64, cert_sig_b64, node_id}` inside `enrollment_tokens.authorization_json` at redeem (C5-4 also polls this shape); `GET /api/hub/enrollments/:id` (session) returns `{status:'pending'|'redeemed', enroll_pk, certificate?, cert_sig?, node_id?}`; hub pushes `enroll.redeemed` to the entry node (exists) and the entry's mesh-runtime forwards it to the browser over `/mesh/ws` as a new Borsh kind `KIND_ENROLL_REDEEMED {enrollPk, certificate, certSig, nodeId}` (add kind + schema + re-export in `packages/shared/src/ws-borsh`, tests). `GET /api/hub/nodes` adds `certificate`/`cert_sig` (b64url) for enrolled nodes.
4. Revoke without races: `POST /api/auth/keylog` gets an optional `?hub=sync` mode: the entry first sends the record to the hub (`key.log.append` over the uplink with a request id and awaits the hub's ack `key.log.ack {id, ok, seq|error}` — add the ack message to both codecs), then applies locally; response `{ok, seq, hash, hubAck: true|false, hubError?}`. The hub's revoke endpoint remains for the hub-machine UI; the frontend will call keylog with `hub=sync` for admit/revoke. Also: `UplinkClient` on (re)connect compares heads and if local > hub, pushes the missing records in order (`key.log.append`), so a record applied while offline reaches the hub later.
5. `/mesh/ws` close code `4401` on session expiry during the connection (5-min re-verify) — verify exists after B2-2b-fix; add a test if missing.
