# Task C5-2 — `direct enable|disable`, pinned native manifest, node-datachannel loader, build-runtime inlining, tarball size check

Context: design `docs/hub/2026082700-hub-node-architecture.md` §5 ("CLI 新命令" `direct enable|disable`, "已确认的取舍" WebRTC dependency row, "直连支持平台"), §3 "node 侧" `RtcPeerManager` 装载方式. Phase-0 facts: `sub/e0-3-result.md` §4 (build-runtime bundling, resources, WASM/native precedents, `--external cpu-features`), `sub/e0-4-result.md` §4 (node-datachannel 0.33.1 package layout: main package `dist/cjs|esm`, `detect-libc`, platform packages `@node-datachannel/<platform>` containing only `node_datachannel.node` + package.json; loader order local build → `require('@node-datachannel/<platform>')`; N-API 8; PoC gotchas: `sendMessageBinary` requires `Buffer`).

`node-datachannel` is **not** installed in the workspace and must not become a runtime dependency of the published package. Steps:

1. **PoC first** (`packages/app/scripts/poc/`, not shipped): add `node-datachannel@0.33.1` as a devDependency of `packages/app` ONLY (`bun add -d --cwd packages/app node-datachannel@0.33.1 --exact` — this is the one allowed install; commit nothing), then write `packages/app/scripts/poc/node-datachannel-loader.ts` proving that the JS layer (`node_modules/node-datachannel/dist/esm/lib/*.mjs` or cjs) can be bundled by `Bun.build` with the native `require` rewritten to an absolute path `<dir>/node_datachannel.node` passed at runtime (env `TMEX_NATIVE_DIR`), and a loopback PeerConnection pair works from the bundle (Buffer send, `remoteFingerprint()`, `localDescription().sdp` fingerprint parse, `bufferedAmount()/maxMessageSize()/setBufferedAmountLowThreshold()/onBufferedAmountLow()`). Record results in the report (this is the "B3-1 must補回環 PoC" item).
2. **Loader** `packages/app/src/lib/native-datachannel.ts` (shared with the gateway later via a tiny interface): `loadNodeDatachannel({nativeDir}) → module | null` — resolves `<nativeDir>/node_datachannel.node`, verifies the manifest integrity (sha256) before `require`, returns `null` (with a logged reason) on any failure so the node reports `direct_capable=false`. Implementation approach must be the one proven in step 1 (e.g. a small vendored copy of the JS layer under `packages/app/src/vendor/node-datachannel/` with the loader line replaced, plus a script `scripts/vendor-node-datachannel.ts` that regenerates it from the pinned version; document the license — node-datachannel is MPL-2.0 — and include the LICENSE file).
3. **Manifest** `packages/app/src/lib/native-manifest.ts`: pinned table for v1 platforms (`darwin-arm64`, `darwin-x64`, `linux-x64-gnu`, `linux-arm64-gnu`): npm package name, version `0.33.1`, tarball URL on registry.npmjs.org, addon path inside the tarball, `integrity` (sha512 from the registry metadata — fetch once with `npm view @node-datachannel/<p>@0.33.1 dist.integrity` / `bun pm view`, and hard-code), N-API version 8. `libc` detection via `detect-libc` logic (vendored) — musl → unsupported.
4. **`direct enable|disable`** in `packages/app/src/commands/direct.ts`: `enable` = detect platform → download tarball → verify integrity → extract the `.node` into `<installDir>/native/` (`install-layout.ts` gains `nativeDir`) → write `native/manifest.json` (platform, version, sha256 of the addon) → print result; failure is non-fatal. `disable` = remove `native/`. `init --role node|hub,node` calls `enable` by default (C5-1 owns `init`; export `enableDirect()` for it and note the one-line hook in the report), `upgrade` re-runs `enable` when the pinned version differs from `native/manifest.json`.
5. **build-runtime**: `packages/app/scripts/build-runtime.ts` — bundle the vendored JS layer (no external), and make sure `hash-wasm` (base64-embedded wasm) and `@noble/*` bundle cleanly; `@simplewebauthn/server` may need `import 'reflect-metadata'` shim per e0-4 §3 — build once, run the produced `dist/runtime/server.js` in test env with `TMEX_ROLES=standalone` to confirm it boots (use a free port, `TMEX_FE_DIST_DIR` pointing to an empty dir, never the production install), and report the tarball/runtime size delta vs `git stash`-free baseline (measure by building at `main`'s `bun run build:tmex:runtime` output size recorded in the report if you can, otherwise report absolute size and the design's < 1 MB budget).
