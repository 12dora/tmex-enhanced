# Task B1-3a-fix — address security review of packages/shared/src/auth/

Context: `packages/shared/src/auth/**` (spec `docs/hub/2026082700-hub-node-architecture.md` §2; original task `sub/b1-3a-prompt.md`, report `sub/b1-3a-result.md` incl. the trailing "指挥官修正"). Reviewer findings: `sub/b1-3a-review.md`. The coordinator judged ALL items valid. Fix each with a regression test that fails before / passes after:

1. `reset-root` is accepted ONLY as genesis: in `verifyKeyLogRecord` reject any `reset-root` unless `ctx.head.seq === 0n && record.seq === 1n && prev_hash == 32 zero bytes` (and expose an explicit `ctx.allowGenesis?: boolean` that the gateway sets only in its local bootstrap path; default false). `verifyKeyLogChain` accepts it only at index 0 and rejects any later `reset-root`.
2. Strict type/signer matrix: `rotate-root` → signer must be `root`; `reset-root` → genesis only (self-signed by payload key); `add-passkey | remove-passkey | set-totp | clear-totp | admit-node | revoke-node` → `root` or `passkey`. Encode the matrix as one exported table `KEY_LOG_SIGNER_MATRIX` and check it before any signature verification (error `signer_not_allowed`).
3. Delegation: verify `exp - issued_at === DELEGATION_TTL_MS`, `issued_at <= now + 60_000` (clock skew allowance, exported constant), `now < exp`. Share the check between the root path and the passkey path (`verifyDelegationTimes(delegation, now)` exported so the gateway's passkey branch uses it too).
4. Fork detection compares the full successor: `existingAtSeq: { bytes, sig }` (or precomputed hash) vs `computeRecordHash(incoming)`; `detectFork` takes `{bytes, sig}` pairs. Also define a canonical binary encoding for passkey-signed record `sig`: Borsh struct `PasskeyAssertion { credential_id: string, client_data_json: bytes, authenticator_data: bytes, signature: bytes }` (export `encodePasskeyAssertion/decodePasskeyAssertion`) — the record's `sig` field for `signer=passkey` is exactly these bytes, so hashes are canonical.
5. Enrollment authorization proof becomes a union: change `Authorization` schema to add `signer: enum{root, passkey}` and `credential_id: option<string>` (append after `root_epoch`), and `AdmitNodePayload.authorization_sig` becomes variable-length `bytes` (root → 64-byte Ed25519; passkey → `PasskeyAssertion` bytes with challenge = sha256(authorization_bytes)). Because passkey verification is async, make `applyKeyLogRecord` async and give it an optional `verifyPasskeyAssertion` in a new `ctx` argument (same hook type as `verifyKeyLogRecord`); root path stays sync-internally. Update `createEnrollment` to produce either form (`PasskeySigner` returns assertion bytes). Update `verifyKeyLogChain` accordingly.
6. `reset-root` reducer: clear `nodeCerts` entirely (plus passkeys/totp as now) and emit effects `revokeAllSessions` + a new `clearPeerCache` effect; `rotate-root` keeps node certs.
7. `admit-node`: reject if `nodeCerts` already has that node_id (revoked or not) → error `node_id_reused`. `revoke-node` on unknown id stays `unknown_node`.
8. Tests: hard-coded expected hex for the Borsh encoding of every signed object (login, authorization, certificate, totpAad, each key-log payload incl. admit-node with both proof forms), join token layout (fixed inputs → fixed 128-char string), delegation challenge, record hash, AES-GCM with a fixed nonce (inject `nonce` via an optional parameter for tests only) ciphertext/tag; a real Ed25519 strict-verify negative vector (a signature that passes ZIP-215 but fails RFC 8032 — take a known test vector from the noble-curves test suite in `node_modules/@noble/curves` if present, otherwise construct a non-canonical S ≥ L or a small-order public key case and prove it flips when `zip215:true`).

Keep every other exported name stable. Document every changed signature in the report (the gateway agent adapts to your report).
