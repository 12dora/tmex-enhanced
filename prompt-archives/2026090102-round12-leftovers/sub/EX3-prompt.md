# EX3 — Mesh node list DTO: slim the 30 s poll

Question: `GET /api/mesh/nodes` returns a rich projection per node (base64 public key, endpoints, inventory, reachability, transport, RTT, direct-failure diagnostics) and the browser polls it every 30 s (single poller since round 11, paused while hidden). Decide whether and how to slim it.

Investigate and report:

1. Server side: `apps/gateway/src/mesh/node-list-projection.ts` and the route handler — every field emitted, its size class, and how it is computed (any per-request cost such as DB reads, RTT probes, inventory joins?). Is the response already gzipped/br by the static/HTTP layer (`packages/app/src/runtime/*`, `apps/gateway/src/api/http.ts`)? Measure a realistic response: build the JSON for ~5 nodes by reading the field shapes and estimate bytes.
2. Client side: every consumer of each DTO field. Start from `packages/api-client/src/auth/types.ts` (mesh node DTO), `apps/fe/src/node/mesh-nodes.ts`, sidebar node section / relay badge, settings → nodes page, node upgrade flow, devices page node groups, direct-carrier controller (does it read endpoints/public key from this DTO or from `/api/mesh/connection`?). Produce a table: field → consumers → needed in steady-state sidebar (yes/no) vs only when settings/diagnostics open.
3. Does the mesh event WebSocket (`apps/fe/src/node/mesh-events.ts`, gateway `mesh/ws*`) already push presence changes? If yes, why is REST polling still needed at 30 s — what state is only reachable via REST (e.g. RTT, reachability probe results)? Could the poll interval be lengthened or made event-driven (poll only on `visibilitychange`/WS reconnect/explicit refresh), which may be a bigger win than DTO slimming?
4. Options: (A) `?view=compact` (or a separate `/api/mesh/nodes/summary`) for the sidebar poller, full projection only for settings/diagnostics; (B) ETag / `If-None-Match` with 304 on unchanged projection (cheap on the wire, no client refactor, but the server still computes the projection); (C) lengthen interval + rely on mesh WS events; (D) do nothing. Quantify bytes/hour saved per option for 5 nodes.
5. Recommend, list affected files (gateway route + projection + api-client types + fe consumers + tests), estimate diff size, and note compatibility: older nodes/hub still serving the full DTO must keep working (mixed-version mesh during rolling upgrade — see `docs/` mesh architecture docs for the version-compat rules).
