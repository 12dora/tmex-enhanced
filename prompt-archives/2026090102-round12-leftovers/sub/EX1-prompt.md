# EX1 — Keep-alive terminals: detach live pane subscription while hidden

Question: hidden keep-alive terminal instances (up to 3) stay mounted and keep receiving live pane output. Design "warm instance, cold subscription": keep the ghostty instance and its screen state, but stop the pane subscription / output delivery while hidden, and resynchronise on re-show.

Investigate and report:

1. Current keep-alive lifecycle: `packages/panels/src/device-console/terminal-keep-alive.ts`, `terminal-stage.tsx`; how a hidden instance is rendered (display:none? offscreen?), how its sink stays registered (`packages/terminal-ui/src/components/hooks/usePaneSinkRegistration.ts`, `packages/stores/src/pane-subscriptions.ts`, `packages/ws-client/src/pane-sink-registry.ts`).
2. Wire protocol: what the gateway sends for a subscribed-but-not-selected pane vs the selected pane (`apps/gateway/src/ws/legacy-feed-broadcaster.ts`, `tmux-command-handlers.ts`): does "subscribed" already imply output delivery? What does the browser send on `select-pane` (history request, `selectPaneWithSize`) — see round 11's viewport-policy changes (`packages/stores/src/select-pane-dispatch.ts`, `packages/stores/src/viewport-policy*` or similar, gateway `viewport` arbitration) because a hidden pane must NOT count as a visible client for the "largest visible client owns the window size" policy. Check whether hidden keep-alive instances currently still report their size / participate in viewport arbitration — that would be a correctness bug on top of the waste.
3. Resync on re-show: what mechanisms exist to restore a pane's screen after a gap — `TERM_HISTORY`, atomic screen snapshot, `capture-pane` based restore (`writeRestoredHistory`, `usePaneSizeSync`), canonical protocol snapshot. Which one can be reused cheaply for "re-subscribe + refresh screen" without a visible flash or duplicated scrollback? Is there a sequence/generation number that lets the client detect it missed output?
4. Interplay with the sink registry buffering (output buffered when no sink exists) — if we unsubscribe on the wire, buffering must not grow unbounded.
5. Option comparison: (A) unsubscribe on hide + full history replay on show (simplest, may duplicate scrollback), (B) unsubscribe on hide + screen-only snapshot on show (keeps old scrollback, screen may be discontinuous), (C) keep subscribed but drop viewport participation only, (D) do nothing (justify if output volume for hidden panes is already negligible because of the gateway's "observed pane" filter).
6. Also check: does the gateway WS heartbeat (`packages/ws-client/src/heartbeat-controller.ts`, `client.ts` visibility handling) currently pause when the page is hidden? Round 11 explicitly left it alone. Briefly state what a "lengthen interval while hidden" change would touch and whether the gateway has a server-side idle timeout that would kill the socket if the interval grows (`apps/gateway/src/ws/index.ts` heartbeat/idle handling).
