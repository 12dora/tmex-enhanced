# Task: production runtime triggers Bun auto-install of `cpu-features` at startup (minutes-long stall)

Scope: `packages/app/scripts/build-runtime.ts`, `packages/app/scripts/*.test.ts` (new test ok), and if truly required `packages/app/src/runtime/**`. Do NOT touch `apps/gateway/src/**`, `packages/shared/**`, `scripts/**`, `apps/fe/**`.

Evidence (real deployment, 2026-08-28): the packaged runtime `dist/runtime/server.js` is built with `--external cpu-features` (ssh2's optional native dep, see `build-runtime.ts` lines ~35 and ~50). At runtime the installed layout has no `node_modules`/`package.json` next to `runtime/server.js`, so when ssh2 does `require('cpu-features')`, **Bun's auto-install kicks in** and tries to download `cpu-features@0.0.10` from the npm registry into `$BUN_INSTALL/install/cache/cpu-features@0.0.10@@@1` (we saw exactly that fd open in the process). On a host with slow/blocked npm access the first start stalls ~5.5 minutes before `[tmex] version` is even printed (module evaluation), then it's cached and later starts take ~1 s. On a fresh container with good network it costs a needless network round-trip at every fresh install. ssh2 wraps the require in try/catch and works fine without the module.

Required fix: make the bundle NOT reference an unresolved bare specifier at runtime. Preferred approach: instead of `--external cpu-features`, use a Bun build plugin / `Bun.build({ plugins: [...] })` (or `--define`/alias if the CLI form of `bun build` supports it — check Bun 1.3.x docs via the local bun binary `bun build --help` and `node_modules/bun-types`) so that `cpu-features` resolves to a tiny virtual module that throws `Error('cpu-features unavailable')` (matching ssh2's optional-dep handling). Check whether `build-runtime.ts` shells out to `bun build` or uses the JS API; converting to the JS API with an `onResolve`/`onLoad` plugin is acceptable. Also audit for any OTHER `--external` entries or dynamic requires in the produced bundle that could trigger auto-install (grep the built `dist/runtime/server.js` for `require("` bare specifiers that are not node: builtins, after building with `bun run build:runtime` in `packages/app`).

Verification (must do): rebuild (`cd packages/app && bun run build:runtime`), then start the built runtime from a temp directory layout with NO node_modules and with `BUN_INSTALL` pointed at an empty temp dir, e.g. env: `NODE_ENV=production DATABASE_URL=<tmp>/t.db GATEWAY_PORT=19985 TMEX_BIND_HOST=127.0.0.1 TMEX_MASTER_KEY=$(openssl rand -hex 32) TMEX_FE_DIST_DIR=<repo>/apps/fe/dist TMEX_MIGRATIONS_DIR=<repo>/apps/gateway/drizzle BUN_INSTALL=<emptytmp>` and confirm (a) `/healthz` OK, (b) no `install/cache/cpu-features*` gets created under the temp BUN_INSTALL, (c) ssh device code path still loads (`bun -e 'await import("<dist>/runtime/server.js")'` is not needed; just ensure the bundle contains no unresolved specifier: `bun build` output must not warn).
