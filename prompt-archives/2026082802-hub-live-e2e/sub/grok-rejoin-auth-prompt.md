# Task: a node that re-joins a hub which already knows it ends up admitted-but-`auth_rejected`; hub must log uplink auth rejections

Scope: `apps/gateway/src/hub/**` (+tests), `apps/gateway/src/auth/user-key-service.ts` / key-log apply code (+tests), `packages/app/src/commands/hub.ts` + `enroll.ts` (+tests), `apps/gateway/src/mesh/integration/mesh.integration.test.ts`, `docs/hub/2026082800-hub-node-operations.md`. Another agent edits `apps/gateway/src/mesh/peer-manager.ts`, `rtc/**`, `packages/shared/src/link/**` — don't touch.

Live evidence (`/Users/konata/code/tmex-enhanced-wt-merge/prompt-archives/2026082802-hub-live-e2e/sub/evidence-home-rejoin.txt`): node `home` (stable nodeId/keypair) joined hub H (fresh) once with token T1 (admitted, then its local write happened to race). It then re-joined the same hub with token T2 using the PoP-capable CLI: redeem OK (PoP accepted), enroll CLI printed `node admitted`, `hub join` exit 0 — but the node's uplink is rejected forever (`[uplink] connect failed … reason=auth_rejected`), and the hub logs NOTHING about why. The redeem-idempotence author noted: "A second admit-node for the same node_id is rejected by the shared keylog (`node_id_reused`)". Hypothesis: the second enrollment mints a NEW node certificate; the enroller signs admit-node #2 which the key log rejects (node_id_reused) — the enroll CLI still prints "node admitted" — so cert #2 is never admitted while the node now presents cert #2 → uplink auth fails; the old admitted cert #1 is gone from the node.

Fix per the design doc (`docs/hub/2026082700-hub-node-architecture.md`): decide and implement one consistent rule — recommended: when a node with an already-admitted identity re-joins the same hub epoch, `hub join` must NOT mint a new certificate; it re-uses the existing admitted cert (fetch it from the hub registry during redeem, verify it is signed for our key, persist it locally) and the enroller/hub skip the second admit (log "already admitted"). If the previous cert was revoked, re-join must fail with a clear error telling the operator to use a fresh identity (`mesh reset`/re-init) — document it. Also: (1) the enroll CLI must not print "node admitted" unless the admit-node record was accepted by the key log (surface `node_id_reused`/other rejection as an error); (2) the hub uplink server must log every auth rejection with a stable reason (`[hub][uplink] auth rejected node=… reason=cert_not_admitted|revoked|bad_sig|epoch|…`, rate-limited) — find the rejection sites in `apps/gateway/src/hub/uplink-server.ts`. Tests: in-process hub + node: join → join again with a new token → uplink online, single admitted cert; revoked → re-join refused with the documented error; enroll CLI reports the key-log rejection.
