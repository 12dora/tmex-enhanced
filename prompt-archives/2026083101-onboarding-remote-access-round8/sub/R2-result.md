## SHOULD-FIX

- **Downloaded archives are extracted without path or integrity validation.** The gateway, CLI, and shell installer pass the release asset directly to `tar -xzf` at [apps/gateway/src/system/upgrade.ts:146](/Users/konata/code/tmex-enhanced-wt-r8/apps/gateway/src/system/upgrade.ts:146), [packages/app/src/commands/upgrade.ts:107](/Users/konata/code/tmex-enhanced-wt-r8/packages/app/src/commands/upgrade.ts:107), and [install.sh:169](/Users/konata/code/tmex-enhanced-wt-r8/install.sh:169). An archive containing absolute paths, `..`, or escaping symlink/hardlink targets can overwrite files outside the staging directory even if the subsequent CLI check fails. `SHA256SUMS` is published but never consumed. Verify the published checksum, reject unsafe member names and link targets using a safe tar library or strict preflight, and preserve `tar` stderr in extraction errors.

- **The detached gateway upgrade has no reliable failure or cleanup path.** State becomes `executing` before the child is known to have spawned, and the child is immediately unreferenced without `error` or `close` handlers ([apps/gateway/src/system/upgrade.ts:71](/Users/konata/code/tmex-enhanced-wt-r8/apps/gateway/src/system/upgrade.ts:71), [apps/gateway/src/system/upgrade.ts:92](/Users/konata/code/tmex-enhanced-wt-r8/apps/gateway/src/system/upgrade.ts:92)). A spawn error can become an unhandled event; an extracted CLI that exits before stopping the service leaves the live gateway permanently stuck in `executing`. Successful upgrades also leave the entire staging directory behind. Wait for the `spawn` event, handle early exit by restoring `idle` with the exit error, and arrange child-side or wrapper-side cleanup after the apply process finishes.

- **Gateway preflight validates only `package/bin/tmex.js`.** [apps/gateway/src/system/upgrade.ts:127](/Users/konata/code/tmex-enhanced-wt-r8/apps/gateway/src/system/upgrade.ts:127) accepts an archive that is missing `package.json`, `dist/cli-node.js`, `dist/runtime/server.js`, or either resources directory. - **Any `node` executable is preferred over the known-good Bun installation.** Both [install.sh:131](/Users/konata/code/tmex-enhanced-wt-r8/install.sh:131) and [packages/app/src/lib/cli-shim.ts:64](/Users/konata/code/tmex-enhanced-wt-r8/packages/app/src/lib/cli-shim.ts:64) select Node without checking its version. An old Node can be present while Bun ≥1.3 was successfully installed, causing the Node-targeted bundle to fail on APIs such as global `fetch`. Require a supported Node version before choosing it, otherwise use the validated baked-in Bun path; also declare the minimum Node version in `package.json`.

- **Release versions are interpolated into URLs and filesystem paths without validation.** Explicit CLI versions are merely trimmed and stripped of `v` ([packages/app/src/lib/release-fetch.ts:17](/Users/konata/code/tmex-enhanced-wt-r8/packages/app/src/lib/release-fetch.ts:17)); the gateway accepts any non-empty API string ([apps/gateway/src/api/system.ts:73](/Users/konata/code/tmex-enhanced-wt-r8/apps/gateway/src/api/system.ts:73)); `TMEX_VERSION` is likewise trusted.
