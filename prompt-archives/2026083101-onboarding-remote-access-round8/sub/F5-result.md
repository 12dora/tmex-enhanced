# F5 — In-place join token in the "Connect More Devices" panel

## What changed

### New files

- `apps/fe/src/pages/settings/nodes/management/use-create-enrollment.ts`
  The single implementation of "create a join token". Extracted verbatim from
  `enrollment-section.tsx` (name state, busy/error, `prompt.request({purpose:'enroll'})` →
  `api.keyLogHead()` → `createEnrollmentOnHub(...)`, `prompt.forget()` on failure,
  `actionErrorText` for the message). Additions over the old inline version:
  - `mode` is now `ResolvedMode | null` — a consumer without a resolved user reports
    `auth.errors.UNKNOWN_USER` instead of not existing. `EnrollmentSection` still passes a
    non-null `ResolvedMode`, so its behaviour is unchanged.
  - `clearedIds` is optional (defaults to a module-level stable empty array).
  - **Self-expiry**: a `setTimeout` on `created.pending.exp` drops the join token from state.
    The settings page already got this through its parent's prune timer + `clearedIds`; the
    side panel has no such parent, and leaving an expired join string in the DOM is exactly
    what the F4-3 review called out.
  - `resolveHubPublicUrl()` moved here; `enrollment-section.tsx` re-exports it so
    `nodes-management.test.tsx` (out of my scope) keeps importing it from the old path.

- `apps/fe/src/components/side-panels/connect-devices/join-command-preview.ts`
  `joinCommandPreview({hubPublicUrl, name, tokenPlaceholder, namePlaceholder})`. It does **not**
  hand-assemble a command: it calls the real `joinCommand()` with shell-safe sentinels
  (`__TMEX_JOIN_TOKEN__` / `__TMEX_NODE_NAME__`) and swaps them for the localized placeholders.
  Consequence: quoting, argument order and the `--name` rule are byte-identical to the real
  command, and an untrusted `hubPublicUrl` falls back to `https://tmex.example.com` (the
  `isTrustedHubUrl` guard still applies, so a malformed hub URL can never reach the preview).
  Note the real command quotes the URL, so the preview reads
  `tmex hub join 'https://hub.example.com' --token <加入码> --name <节点名称>`.

- `apps/fe/src/components/side-panels/connect-devices/join-token.tsx`
  `useJoinEnrollment()` wires the panel's own copy of the deps: `useSharedAuthMode()` →
  `useHubNode([], {enabled: meshEnabled, hubNodeId: mode.hubNodeId})` (hub is located purely
  from `/api/auth/mode`, so the mesh node list is not pulled into the side panel),
  `usePasskeys` + `useCredentialPrompt`, then `useCreateEnrollment`. `JoinTokenFields` renders
  four states: not mesh → `token.unavailable` + settings link; mesh but no trusted hub URL →
  `nodes.enrollment.missingHubUrl` + settings link; ready → node-name `Input`
  (`nodes.setup.fields.name`) + 「生成加入码」 (`nodes.enrollment.create`, disabled while busy or
  while the hub probe has not succeeded, with the `nodes.hubOffline` title); after success →
  copyable token (`nodes.enrollment.joinToken`) + `nodes.enrollment.joinHint`.

## Step 6 (requirement 4) — deliberately not fully wired

Step 6 keeps its static description plus a live 「等待新节点加入」 line while a token is
outstanding (`create.created !== null`, which the hook clears on expiry). The 「确认加入」 button
was **not** wired, for a concrete reason rather than effort: admission needs
`useEnrollmentWatch` + `useAdmitAction` plus the orchestration that lives in
`nodes-management.tsx` (pending store, prune timer, expired/cancelled/admitted id sets).
`nodes-management.tsx` is outside my scope, so I could not refactor that orchestration into a
shared place — I could only duplicate it. Two independent admit engines running at once (panel
open + settings page mounted) is actively dangerous here: `admitPlan`/`submitAdmitRecord`
document an unrecoverable `seq_gap` fork if a second signer re-signs an admit record at a new
head. If step 6 should become fully interactive, the right move is a follow-up that lifts the
admit orchestration out of `nodes-management.tsx` into a hook both consumers share.
