Owned files: `apps/gateway/src/ws/borsh/switch-barrier.ts` (+ `switch-barrier.test.ts`), `apps/gateway/src/mesh/rtc/data-channel-carrier.ts` (+ test), the carrier interface file (`apps/gateway/src/ws/carrier.ts` or wherever `Carrier`/`CarrierSendResult` is declared — only to ADD one optional method), `apps/gateway/src/ws/tmux-command-handlers.ts` only if needed. Result file: `/Users/konata/code/tmex-enhanced/prompt-archives/2026083102-relay-files-switch-lan-round9/sub/G2c-result.md`

## What to do (exactly)
1. **Revert the DataChannelCarrier contract change from G2b**: `send()` must again return `'sent'` when the first fragment was accepted and the remainder is saved for internal continuation (`onBufferedAmountLow → flushRemainder → onDrain`), exactly as before G2b. Keep the pre-existing rule that a NEW frame while a remainder is pending returns `'backpressure'`. Update `data-channel-carrier.test.ts` accordingly (the 70 KiB test stays but asserts `'sent'` + remainder flushed on drain).
2. **Add an optional carrier capability** `hasPendingWrites?(): boolean` to the Carrier interface; implement it on `DataChannelCarrier` as `remainder !== null || bufferedAmount above the high-water mark used by send()`. Do not implement it on the WebSocket/other carriers (undefined ⇒ treated as false).
3. **SwitchBarrier**: remove ALL of G2b's drain machinery — no `carrier.onDrain` subscriptions, no `awaitingLiveResume` flags, no `gatewayWebSocketSendGuard.handleDrain()` calls from the barrier (including the one added in `cancelTransaction`). Replace with a small gate used right before sending `LIVE_RESUME` (both the wantHistory:false path after ACK and the after-history path): if `session.activeCarrier.hasPendingWrites?.()` is true, keep output buffering and re-check on a timer (25ms) until it is false, then send. The wait must be: (a) token/pending-scoped — capture the pending object + selectToken at scheduling time and abort silently if `getPending(session, deviceId)` is no longer that object or the token changed or the session/carrier closed; (b) bounded — deadline 1500ms from the first check (reuse the existing history-timeout constant), on deadline fall back to the previous behaviour (send anyway; if that returns backpressure → the pre-G2b failure handling: stop buffering, complete the transaction via LEGAL state transitions — never `ACKED → STABLE`; if the state is ACKED use the SELECT_FAILED path); (c) timers registered in `pending.timers` so cancelTransaction/cleanup clears them. Because the DataChannel carrier reports pending writes only while a remainder exists (drains in milliseconds), this keeps G2's "resume immediately after history" for WebSocket sessions and adds only the few ms of real drain time on DataChannel sessions.
4. History send returning `'backpressure'` (frame NOT accepted): keep the pre-G2b handling (markStreamGap + the existing timeout path) — do not invent new behaviour.
5. Fix the pre-existing illegal transition noted in review-E blocker 2 only if it is on your path: when a send fails in ACKED state, route through `SELECT_FAILED → STABLE` instead of calling `completeTransaction()` directly.
6. Tests (switch-barrier.test.ts): (a) carrier with `hasPendingWrites` true for the first N checks → LIVE_RESUME is sent only after it turns false, buffering stays on meanwhile, fake timers/scheduler if the file already has one (otherwise real timers with small values); (b) token changes during the wait → nothing sent for the old token, new transaction unaffected; (c) deadline expiry → resume sent anyway; (d) cancelTransaction during the wait clears the timer (no late send); (e) WebSocket-style carrier without hasPendingWrites → immediate resume (regression guard for G2). Remove/replace G2b tests that encode the drain-callback design.
