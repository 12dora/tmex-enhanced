## Reviewer findings on G3 (all verified against the code — fix every one)

Blocker 1 — `dialDirect()` (~`peer-manager.ts:1591–1640`) runs `track()` + `rememberKeys()` BEFORE the race picks a winner (`raceWsSecureEndpoints` ~`:1516`). `track()` does not guarantee it returns the candidate it was given: when an equal-rank live link exists it may park the candidate and return the existing session. The loser branch then closes whatever was returned (`session.close('ws-race-lost')`) — which can be the real winner. Scenario: A and B handshakes settle in the same event-loop turn; A's dialDirect installs session A; B's track() parks B and returns session A (and rememberKeys writes B's keys onto A); A is elected winner; B's loser callback closes session A → getLink may return a closed session and keys mismatch the live link. Fix: a per-endpoint dial must return only an authenticated-but-untracked candidate (session + keys); `raceWsSecureEndpoints` elects the winner atomically, then calls track()/rememberKeys() for the winner only; losers close only their own handshake session. Add a deterministic test where two handshakes succeed in the same turn and assert returned session, live session and keys all belong to the same candidate.

Blocker 2 — `dialDirect()` ~`:1597`: `abortable(Promise.resolve(this.wsFactory(url)), signal)` only rejects the wrapper; when the child is aborted (a sibling won, or `stop()`) while `wsFactory` is still pending, the factory's WebSocket later resolves into a local variable nobody owns → leaked socket per race/stop. Fix: keep the original factory promise and attach a late-result handler that closes the transport immediately if the signal is already aborted (or if the dial already finished). Add two tests (winner-aborts-loser and stop()-during-race) where the factory resolves after abort, asserting the late socket gets closed. The existing "late handshake" test must also assert the returned transport is closed.

Should fix 1 — `recordDirectFailure()` (~`:1421`) merges missing fields from the previous record, and with an existing relay link `liveOf` (~`:1435`) returns before the DC result is recorded, so `/api/mesh/nodes.directFailure` can show a stale dc reason with a new timestamp. Fix: build one attempt record per `dial()` invocation, collect ws/dc outcomes within that attempt, commit it once before returning an existing relay or creating a new relay; never merge fields across attempts; a successful direct link still clears the record. Test: existing relay → capability change → background upgrade fails → record reflects only this attempt.

Should fix 2 — `linkDetailOf()` (~`:533`) calls `listPeers().find(...)` (full `peer_cache` scan + transform) per node while `collectNodes()` in mesh-routes already built `peerById` → O(N²) on `/api/mesh/nodes`. Fix: use `userStore.getPeer(nodeId)` (primary-key lookup) or, better, have the projection supply endpoints from the already-built `peerById` and keep `linkDetailOf` DB-free.
