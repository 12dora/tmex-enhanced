## Product decision (already made with the user)
A second machine must be able to join an existing relay tenant with just **relay URL + tenant id + the mesh account password**, no `r3.` join string. Design ("sealed pack"):
- The relay stores per tenant: public KDF params (`kdf_params_json`) and an opaque `sealed_pack` blob it cannot decrypt.
- `sealed_pack = seal(KEK, plaintext)`, `KEK = HKDF-SHA256(root_seed, salt = utf8("tmex-relay-pack/v1"), info = tenant_id(16B), 32)`; AES-256-GCM with AAD = `utf8("tmex-relay-pack/v1") ‖ tenant_id(16) ‖ root_public_key(32) ‖ root_epoch(u32 LE)`; plaintext (Borsh or fixed layout, your call, documented) = `{ v:u8=1, K_log(32), token(32), head_seq(u64), head_hash(32), issued_at(u64) }`. New shared module `packages/shared/src/relay/relay-pack.ts` (+test), browser + Bun compatible (WebCrypto + @noble hkdf like `tenant-cipher.ts`), zeroing buffers after use. Root seed comes from `deriveSeed(password, kdfParams)` (`packages/shared/src/auth/root-key.ts`).
- Joining machine: `GET <relay>/api/relay/tenants/:id/kdf` (unauthenticated, rate-limited, 404 for unknown tenant) → derive root key from password → sign the existing `tmex/relay-enroll/v1` proof → `POST /api/relay/enroll` with `mode: 'join'` and `tenant_id` → relay verifies proof against **that tenant's current root public key**, checks root_epoch, and returns `{ tenant_id, kdf_params, sealed_pack, root_epoch, key_log_head_seq }` **without** touching tokens (no `issueTenantToken`, no `enforceTokenReissue`, no site-password check; keep `mode` absent/`'enroll'` behaving exactly as today) → node opens the pack → downloads the encrypted key log with the token (existing key-log page endpoint used by redeem / `relay.keylog.req` — reuse `packages/app/src/lib/relay-keylog.ts`), verifies the chain, **verifies the record at `head_seq` has hash `head_hash`** (fail closed if the log is shorter), replays with the passkey replay verifier → creates its own node identity + self-signed certificate with the root key (`node-identity-service.ts` `selfSignedNodeCertificate()`) → appends TWO records atomically under the key-log write lock: root-signed `admit-node` (self) then `meta-key` (epoch+1, fresh K_meta wrapped to every admitted node including itself; reuse the `meta-key/prepare` builder logic) → persists user/root state, `mesh_relays` (from the replayed `set-relays` projection; the joined relay url must be present) and `mesh_secrets` (K_log epoch 0, new K_meta) → uploads both records to the relay (`relay.keylog.append` with the `admit` member sidecar, or the HTTP append path the CLI uses) → re-seals and uploads the pack with the new head (`POST /api/relay/tenants/:id/pack`) → writes env (`TMEX_ROLES=node` or keeps `relay,node`, `TMEX_HUB_URL=''`) → restart. Implement this as a reusable `performRelayPasswordJoin(input, deps)` in `packages/app/src/commands/relay-password-join.ts` (mirroring `relay-join.ts` / `performHubJoin` structure so both the CLI and the web setup route can call it), exporting also `runRelayPasswordJoin(parsed, io)` for the CLI (`tmex relay join <url> --tenant <id> [--password] [--name] [--ca-fingerprint] [--no-restart]`; the args/dispatch wiring in `args.ts`/`cli-auth-entry.ts` is done by another agent — they will import exactly `runRelayPasswordJoin` from `../commands/relay-password-join`).
- Pack upload route (relay side) `POST /api/relay/tenants/:id/pack` authenticated with the tenant token header like the other tenant routes; body `{ sealed_pack, kdf_params, root_epoch, head_seq }`; server checks root_epoch == tenant's, `head_seq <= relay key_log_head_seq` (so a pack can never claim a head the relay does not have), size limits; stores in a transaction.
