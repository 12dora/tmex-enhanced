## Findings (all confirmed by review of the current code; fix each, with tests)
1. `relay-metrics.ts` ~:200 — `framesInPerSec/framesOutPerSec` are computed from the sum of cumulative counters of the *currently online* links. When a link closes or is replaced between two samples its counters vanish from the sum, the total drops, and `perSec()` clamps the negative delta to 0, hiding traffic from other links. Fix: keep process-level monotonic retired totals — when a link is removed/replaced, fold its final `stats()` into `retired{framesIn,framesOut,bytesIn,bytesOut}`; the sampled cumulative value = retired + Σ online. Also give `WebSocketLink` (packages/shared) a public `stats()` delegating to its mux instead of reading a private field via duck-typing. Test: link closes between samples, rate stays correct; link replaced (reconnect) between samples.
2. `relay-metrics.ts` ~:221 — for a tenant/member key that has no `previous` entry, `previous.get(key) ?? curr` uses the current value as the old value, so the first sampling window of a new member/tenant always reports 0 rate. Fix: once a baseline sample exists, a missing key means previous = 0; if `curr < prev` treat as a counter reset (rate from 0). Tests for a new member's first window and for a reset.
3. `relay-uplink-server.ts` ~:455-461 — while a pong is still pending, every heartbeat overwrites `pingAt` and sends another ping, so a late pong is matched against the newest ping and RTT is under-estimated. Fix: while awaiting a pong only count a miss / check the timeout; do not overwrite `pingAt` or send a second concurrent ping; allow the next ping only after the pong (or after the miss-limit disconnect). Test: pong arrives after more than one heartbeat period → RTT measured from the original ping.
4. `relay-metering.ts` ~:65 and `relay-registry.ts` ~:62 — per-member live counters (`liveMembers`), `reconnects` and `seen` are never cleaned when a member is revoked, and tenant deletion only calls `metering.forget()` without clearing registry reconnect state. Revoked nodes don't count against quota, so a tenant can grow these maps without bound, and a re-created member with the same id inherits old reconnect counts. Fix: add `forgetMember(tenantId, nodeId)` / `forgetTenant(tenantId)` on both the metering and the registry bookkeeping, call them on the revoke path and the tenant-delete path (find the exact call sites: `relay-admin-routes.ts` tenant delete / kick, and wherever `status = 'revoked'` is written), idempotent even if a stream close callback fires afterwards. Tests.
5. `packages/api-client/src/relay/admin-api.ts` ~:173 — `metrics({ members: false })` returns a body without `members` but is typed `Promise<RelayMetricsResponse>` where `members` is required. Fix with an overload: `metrics(opts: { members: false }): Promise<Omit<RelayMetricsResponse, 'members'>>` and the default overload returning the full type. Do not make `members` optional in the main type. Test.
