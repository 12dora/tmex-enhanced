## Findings to fix (from code review of commit 86064bf2; verify each against the current code first)
1. `forwarder.ts` ~:689 — the `nodeId` taken from the `/n/:nodeId/*` path is interpolated into the clearing `Set-Cookie` name without validation. A plain GET to `/n/self%3D/ws` makes `upgrade()` return false and yields `tmex_s_self==; …; Max-Age=0`, which browsers parse as cookie `tmex_s_self` → deletes the entry's own login session; the same trick can clear any other node cookie via cross-site navigation. Fix: only emit the clearing cookie when the target node id strictly matches the canonical 32-hex node id format (reuse the existing node-id validator if one exists — grep for `HEX32`/`isNodeId`); for anything else, no cookie at all (and decide whether a malformed id should be 404 earlier in the route — keep existing behaviour for that unless trivially safe). Add regression tests for `%3D`, `;`, control characters and an uppercase/short id.
2. `forwarder.ts` ~:335 and ~:627 — `safeUnreachableReason` is derived from `lastError` before checking whether the request signal was aborted, so a mid-flight cancel is classified as `no_link` (or reports the previous attempt's reason) and `timeout` never surfaces for the common cancel path. Fix: check `signal.aborted` / the abort controller first and map it to `timeout` (or `aborted` if you add it to the whitelist in packages/shared `NodeUnreachableReason` — only if you can also edit that type; otherwise map to `timeout`), then classify `lastError`. Add tests: abort during `openHttpStream` for plain forwarding and for `forwardAuthorizedHttp`.
3. `peer-manager.ts` ~:1132 — the new `[mesh][relay] accept failed node=… reason=…` log prints the handshake error message with only CR/LF/TAB stripped; a peer can inject ESC / C0 / C1 control sequences via the handshake `t` string or a stream RST reason. Fix: log a whitelisted category (e.g. `PeerHandshakeError.code`, `LinkError.code`, else `unknown`) plus a summary with ALL control characters (U+0000–U+001F, U+007F–U+009F) removed and length-capped at 120. Add a test with a malicious handshake message (peer-manager.test.ts is now in scope).
