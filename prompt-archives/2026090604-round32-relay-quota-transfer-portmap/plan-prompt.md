## 2026-09-06 初始 prompt

继续开发, 请你分批commit并在最后push替换本机tmex, Think in English, Send English prompt.
任务：
1. 中继运营
    1. 应该允许对租户设置最大文件限制(避免用户用文件传输超大文件占满服务器带宽)
    2. 运行设置最大租户, 超过上限后新租户无法加入
    3. 允许设置最大中继带宽, 例如最大带宽10M, 即所有租户加起来带宽不超10M,你应该对各租户带宽进行合理分配
    4. 设置租户带宽公平分配, 如资源紧张时避免某租户消耗完所有带宽而其他租户分配不到
2. 管理设备右上角新增三点菜单, 将恢复布局折叠进菜单
    1. 新增文件传输(该功能允许用户在任意2个终端之间传输文件)
        1. 点击后弹框, 弹框采用左右分栏, 该弹框左侧显示A机文件系统,右侧显示B机文件系统(需要用户先在左侧, 右侧选择A, B机), 左右各有发送按钮, 点击左侧发送A机选择的文件/文件夹(允许多选)到B机, 右侧同理
        2. 弹框下方有传输列表, 显示当前正在传输和已经传输完成的任务(要求显示速度, 文件大小等基本信息)
    2. 新增端口映射, 该功能允许用户在A/B机之间建立端口映射通道
        1. 例如可以把B机的12345端口映射到A机的5678端口, 这样A机访问5678端口就相当于访问B机的12345端口
        2. 弹框中有列表显示当前已映射的端口, 允许暂停,删除
        3. A机/B机是连接到tmex的任意机
        4. 你要注意检测已被占用端口, 并不允许用户映射这些端口
    3. 1和2两项功能必须在hub和中继模式下work, 其中中继模式要遵循配额和公平分配
        1. 这两项功能需要深度优化网络传输性能, 例如文件传输应该支持切片多线程断点续传等(你需要使已有的文件传输也共享这些优化, 采用同一套上游). 端口映射也需要深度优化各网络环境的性能
    4. 在过程中如果你发现bug, 顺便解决; 如果发现同一个代码多处复制, 你应该抽成1个上游, 避免霰弹式修改
