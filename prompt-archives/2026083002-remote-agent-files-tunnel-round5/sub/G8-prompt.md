Context: the Remote access feature (read `G4-result.md`, `G6-result.md`) currently refuses public tunnels on a standalone (no-login) instance with `auth_required`. The product decision is now: Cloudflare Access is an OPTIONAL protection layer (a pure-LAN user may not need it); the other protection is the mesh login system (username / password / 2FA, `loginEnforced`). The backend never hard-blocks, but when the instance is unprotected (`exposureProtected === false`) any action that exposes it (`quick_start`, `create`, `start`, `set_auto_start(true)`) must carry `acknowledgeExposure: true`, otherwise 409 `exposure_ack_required`. The gateway verifies Access JWTs itself when enforcement is on. The contract was extended by the commander — read `packages/shared/src/contracts/tunnel.ts` in full: `TunnelAccessStatus`, `TunnelAccessPolicyRule`, `TunnelStatusResponse.access` / `loginEnforced`, actions `set_access_credentials` / `clear_access_credentials` / `configure_access` / `remove_access` / `set_access_enforce`, job kind `access`, error codes `access_api_failed` / `access_required`. The frontend (agent O11) is built in parallel against it.

2. Credentials: `set_access_credentials` stores the API token encrypted (reuse the crypto used by tls-config-store / secrets) + account id; validate immediately by calling the organizations endpoint (→ teamDomain) and return `access_api_failed` with the sanitized message on failure. `clear_access_credentials` wipes them.
3. `configure_access` (async job `access`, steps `create_app` → `policy` → `verify`): requires `config.hostname` (named mode) and credentials; create the app for the hostname if `appId` is null (else update name/domain), then create-or-replace ONE allow policy with the given rules (at least one rule required; validate emails and domains); read back `aud`; persist appId/aud/hostname/rules; set `enforceJwt = true` by default. `remove_access` deletes the app (best-effort) and clears state. `set_access_enforce` toggles enforcement.
4. Enforcement guard: when `access.enforceJwt && access.configured`, any incoming HTTP/WS upgrade request that carries `cf-connecting-ip` (i.e. arrived through cloudflared) must present a valid JWT (`Cf-Access-Jwt-Assertion` header or `CF_Authorization` cookie): verify RS256 signature against the cached JWKS (refresh on unknown kid, cache ≤ 10 min, fetch injectable), `iss`, `aud` includes stored AUD, `exp`/`nbf`. Failure → 403 JSON `{ error: { code: 'access_denied' } }` (or close the WS). Requests without `cf-connecting-ip` (LAN/loopback) are untouched. Never log tokens.
5. Exposure gating (REPLACES G6's `auth_required` refusal — remove that refusal): status carries `loginEnforced` (mesh login enforced) and `exposureProtected = loginEnforced || (access.configured && access.enforceJwt && access.hostname === config.hostname)`. Persist the acknowledgement with the config (`exposure_acknowledged_at`) so boot auto-start of an unprotected instance is allowed only if it was acknowledged; otherwise skip auto-start with a warning log. `auth_required` stays in the contract but is no longer emitted.
