# G5 — Hub-to-hub relay (nodes attached to different hubs can reach each other) + attachedHubId

Result file: `/Users/konata/code/tmex-enhanced-wt-r14/prompt-archives/2026090200-round14-multihub-phase2-nodes-mgmt/sub/G5-result.md`

## Background
Relay today only works between nodes attached to the same hub: `UplinkServer.onIncomingStream()` (`apps/gateway/src/hub/uplink-server.ts` ~L1049-1090) looks the target up in the in-process `NodeRegistry` and pumps the two streams; `rtc.signal` forwarding (~L1007-1033) likewise. After a failover or with attach-to-nearest (next task) nodes end up on different hubs and become mutually unreachable. Exploration with exact refs and a proposed design: `sub/EX1-result.md` §1 (read fully; verify against code). Hub↔hub connectivity already exists: every standby keeps a node-style uplink to the writer (authenticated, CA-pinned), and hub authorization is `isAuthorizedHub()` (`apps/gateway/src/hub/hub-authorization.ts`). Standby write forwarding / token frame were added in G4 (`sub/G4-result.md`) — reuse its version gating for new control frames.

## Requirements
1. **Attachment routing table** (new `apps/gateway/src/hub/attachment-router.ts`, in-memory): `nodeId → { hubId, version, lastSeen }`. Local attachments come from the local `NodeRegistry`. Hub-only control frame `hub.attachments { revision, entries: [{nodeId, attached: boolean}] }` (append to `UPLINK_CTL_TYPES` at the end; only exchanged between hubs passing `isAuthorizedHub`, only to peers advertising version ≥ 1.1.13): a standby sends its full local set on (re)authentication and deltas on attach/detach; the writer merges and re-broadcasts the union to all authorized hubs (so hubs learn about each other via the writer; a two-hub mesh needs no extra link). Entries expire after 5 min without refresh; cap 4096 entries / frame 64 KiB; reject frames from unauthorized peers.
2. **`node.list.nodes[].attachedHubId`** (optional field appended to the node entry codec, legacy-stripped for old peers) — projected by the writer from the routing table so nodes and the FE (`GET /api/mesh/nodes` → `MeshNode.attachedHubId?`) can see where each node hangs; add the field to `apps/gateway/src/mesh/node-list-projection.ts` and the `/api/mesh/nodes` projection in `mesh-routes.ts` (surgical edit; another agent may be editing other parts of that file — re-read before editing) and to `packages/api-client/src/auth/types.ts` `MeshNode`.
3. **Cross-hub relay**: in `onIncomingStream()` when the target is not local but the router says `hubId = H`: open a `hub-relay` stream on the authenticated uplink between this hub and H (standby→writer uplink, or writer→standby via the same link in the other direction — check the `LinkStream` mux supports opening streams from the server side; `packages/shared/src/link/mux.ts`) with OPEN payload `{ kind: 'hub-relay', to: nodeId, from: nodeId, originHubId, visitedHubIds: [...], hop }` and pump bidirectionally; H validates (`isAuthorizedHub(origin)`, `hop ≤ 2`, `visitedHubIds` has no repeats, target local and same user, source cert not revoked) then pumps into the local target exactly like a local relay. Hubs only forward the already end-to-end-encrypted relay payload; they never terminate the node↔node handshake. On uplink loss, reset the in-flight cross-hub streams (no migration).
4. **`rtc.signal` across hubs**: wrap in hub-only `hub.forward { kind: 'rtc.signal', originHubId, returnHubId, visitedHubIds, signal }`; the target hub injects into its local signalling path; replies route back via `returnHubId`. Session→hub mapping entries TTL 10 min.
5. **Failover behaviour**: when a node re-attaches elsewhere, the new hub's attachment delta supersedes (higher `lastSeen` wins); stale entries pointing at an offline hub are dropped when that hub's uplink is gone.
