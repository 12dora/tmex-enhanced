- Hypothesis from the harness author: `apps/gateway/src/mesh/mesh-routes.ts` `collectNodes` (~L206–218) builds the list from `userStore.listCerts()` + self; `hub join` only stores the hub's certificate; the uplink's `node.list` handling in `apps/gateway/src/mesh/uplink-client.ts` / `mesh-runtime.ts` may not be persisting other nodes' certs / `hub_meta` (`isHub`, `hubNodeId`) into the local store — or the hub may not be pushing `node.list` to non-hub uplinks with the other nodes' certs / admit records at all. Check also how `admit-node` key-log records propagate: node-b's admit record was appended on the hub by the `enroll` process (root-key signer); does node-a ever receive the key log tail (`/api/auth/keylog` sync, uplink push) so that node-b's cert becomes trusted locally? The design says certs are only trusted after the `admit-node` record is in the user key log.
