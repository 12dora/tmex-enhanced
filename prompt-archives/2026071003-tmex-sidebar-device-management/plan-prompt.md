# 原始需求归档

日期：2026-07-10

## 用户需求

我们开新的 worktree，基于当前 submodule tmex 版本进行同步迭代。

tmex 侧：

1. 整个前端设备管理不再区分已连接／未连接态。
   1. 侧边栏删除连接／断开按钮，新增展开／收起状态（不要改 UI 结构和风格），展开收起状态本地储存。
   2. 设备管理页面删除连接按钮。
   3. 侧边栏的高亮状态变成以当前前端的终端为准，不再依赖 tmux 自己的 active 状态。
2. 侧边栏把 Agent 放在最上面。
   1. Agent 展开时其他一级树收起。
   2. 允许 Panes 和 Files 同时展开。如果展开 Panes 和 Files 时 Agent 已展开，则自动收起 Agent。
   3. 适当调整侧边栏一级条目图标文字样式，并在最上方添加适当间隙使视觉平衡。

Vibex Webapp：

1. Webapp 的样式应按照 tmex 的风格来而不是 VibeCafe 的（写入文档和规范）。
2. Webapp 应移植完整的当前 tmex 布局和样式。
3. Webapp 应完整实现除 Agent 外的所有功能。
4. 设备管理／侧边栏设备列表，应混合显示所有 instance 里的所有设备。

先做 tmex；用户验收通过后再做 Webapp。tmex 和 Webapp 工作时都应开着 devserver 方便随时查看。tmex 应从 `/Users/krhougs/LocalCodes/tmex` 复制开发数据库。验收时注意原始需求和深度，避免偏离需求。

## 执行边界

本 plan 的实施阶段只覆盖 tmex。Vibe X Webapp 的需求已在 Vibex 文档中存档，待 tmex 验收通过后单独开计划，不在本阶段提前改动。

## 验收反馈（2026-07-10）

用户在 tmex 验收中追加以下调整：

1. 设备默认展开。
2. disclosure 箭头移到设备行最右；恢复此前删除的在线／离线视觉标识。
3. 恢复设备到 window 层级的缩进。

该反馈覆盖本计划中“设备树默认收起”的先行决策。连接／断开按钮和用户可操作的连接意图仍保持移除；在线／离线点仅展示底层运行时实际状态，不提供交互，也不改变设备树可见性。
